# 2. Item 1 — NVIDIA·H200·Groq LPU

## 판정: **중대한 수정 필요**

### A. Primary URL이 FT의 통상적인 기사 URL 형식과 맞지 않음

제시된 주소:

```text
https://www.ft.com/content/nvidia-china-h200-shipments-bytedance-tencent
```

Financial Times의 개별 기사는 통상 `/content/` 뒤에 **UUID 형태의 콘텐츠 ID**를 사용합니다. 위 주소처럼 사람이 읽는 제목 슬러그만 붙인 URL은 비정상적이며, 원문 링크로 신뢰하기 어렵습니다.

따라서 실제 FT 기사 URL 또는 FT 콘텐츠 ID를 다시 확인해야 합니다.

### B. 승인·할당·선적·수령이 서로 다른 사건인데 혼용됨

초안은 다음 표현을 번갈아 사용합니다.

- “received their first combined shipment”
- “initial allocation”
- “following import clearance”
- “hardware actively delivered”
- “undergoing datacenter rack integration”

중국 당국의 구매·수입 승인이나 NVIDIA의 할당이 있었다고 해서 실제 제품이 고객 데이터센터에 **도착해 설치 중이라는 뜻은 아닙니다**. 원문이 “approval”, “allocation”, “order” 또는 “shipment preparation”이라고 보도했다면 “received”와 “rack integration”은 과장입니다.

다음 단계들을 분리해야 합니다.

1. 미국 수출 허가
2. 중국 측 구매·수입 승인
3. NVIDIA의 고객 할당
4. 물리적 선적
5. 고객 수령
6. 서버 통합·가동

### C. 프리필과 디코딩의 병목 설명이 사실상 반대로 되어 있음

초안:

> “memory-bandwidth-heavy prefill operations from compute-bound token decoding stages”

일반적인 Transformer 추론에서는 대체로 다음과 같습니다.

- **Prefill:** 큰 행렬 연산 비중이 높아 상대적으로 compute-bound
- **Autoregressive decoding:** 토큰마다 모델 가중치를 반복적으로 읽기 때문에 상대적으로 memory-bandwidth-bound

배치 크기, 모델 구조, 양자화 및 speculative decoding 등에 따라 달라질 수 있지만, 초안의 일반화는 통상적인 설명과 반대입니다.

수정 예:

> “compute-intensive prefill과 메모리 대역폭에 민감한 autoregressive decoding을 분리하는 이기종 서빙 구조”

### D. “추론 전용이므로 수출 규제 준수”라는 논리는 성립하지 않음

초안은 LPU가 추론에 집중하기 때문에 일반 훈련용 FLOPs가 부족해 규제를 피할 수 있다는 취지로 설명합니다. 그러나 미국의 첨단 컴퓨팅 수출 규제는 단순히 제조사가 제품을 “추론용”이라고 부르는지 여부가 아니라, 실제 처리 성능·성능 밀도·상호연결 및 최종 용도 같은 기준을 봅니다.

따라서 다음 문장은 근거 없이 단정적입니다.

> “achieves compliance by focusing strictly on deterministic inference execution”

정확한 ECCN, 적용 성능 기준, 라이선스 조건을 제시하지 않는 한 “규제 준수 가능성을 검토한다” 정도로 낮춰야 합니다.

### E. Groq 관련 기술 세부사항은 출처로 확인되지 않은 설계 추정으로 보임

다음 주장은 각각 별도 근거가 필요합니다.

- NVIDIA가 Groq의 LPU 아키텍처를 라이선스했다는 점
- Vera Rubin 호스트에서 드라이버로 분리했다는 점
- 독립 PCIe 카드로 배포한다는 점
- 2026년 말 상용 출하 일정
- 현재 고객 샘플링 중이라는 점
- 구조적 성능 제한 없이 수출 기준을 통과한다는 점

라이선스 발표가 사실이더라도, 그것이 곧 **Groq 칩을 거의 그대로 쓴 NVIDIA PCIe 제품**이나 특정 드라이버 구조를 의미하지는 않습니다.

### F. 수량 표현도 재확인 필요

다음 수치는 서로 독립적인 검증이 필요합니다.

- 합계 20,000개
- ByteDance와 Tencent 각각 약 10,000개
- 중국용 H200 재고 500,000개

“20,000개 합계”가 사실이어도 이를 자동으로 10,000개씩 나눈 것은 오류일 수 있습니다. 원문에 고객별 물량이 없다면 배분치를 삭제해야 합니다.

### 권고 제목

> **중국 당국이 ByteDance·Tencent의 NVIDIA H200 도입을 승인한 것으로 보도; 실제 인도 여부와 Groq 기반 제품 세부사항은 추가 확인 필요**

# 3. Item 2 — Thomson Reuters·CoCounsel·Claude Agent SDK

## 판정: **핵심 사건은 가능하지만 명시적 제품·아키텍처 오류 포함**

### A. Shepard’s와 KeyCite를 혼합한 것은 명백한 오류

초안:

> “validates primary case law citations against active Shepard's/KeyCite authorities”

- **KeyCite:** Thomson Reuters / Westlaw
- **Shepard’s:** LexisNexis

Thomson Reuters 자체 제품 기능을 설명하면서 “Shepard’s/KeyCite”를 하나의 내부 검증 체계처럼 표현하면 안 됩니다.

수정:

> “validates citations and subsequent treatment through Westlaw’s KeyCite”

### B. 공식 URL은 형식상 가능하지만 실제 페이지 확인이 필요

제시된 URL은 Thomson Reuters 보도자료 형식으로는 그럴듯합니다.

```text
https://www.thomsonreuters.com/en/press-releases/2026/august/thomson-reuters-launches-next-generation-cocounsel-legal.html
```

다만 초안에는 HTTP 접근 결과, 공식 제목, 게시 시각이 없습니다. URL이 실제로 열리는지, canonical URL과 제목이 일치하는지 확인한 후 사용해야 합니다.

### C. “Claude Agent SDK 직접 통합”의 범위를 구분해야 함

다음은 서로 다른 주장입니다.

- CoCounsel이 Anthropic 모델을 사용
- Claude API의 tool use를 사용
- Claude Agent SDK를 제품 오케스트레이션 계층으로 직접 사용
- Westlaw와 Practical Law 전체에 SDK가 임베드됨

공식 발표에 정확히 **Claude Agent SDK**가 명시돼 있지 않다면, 단순 모델 공급 관계를 SDK 통합으로 확대해서는 안 됩니다.

### D. “Westlaw Brief Builder” 기능 범위가 지나치게 구체적

다음 기능은 공식 제품 문서로 각각 확인해야 합니다.

- 완전한 소송 서면 초안 작성
- 관할권 충돌 판례 자동 해결
- 사실 분석부터 논증 구조까지 전 과정 자동화
- 결정론적 환각 검사
- 모든 인용의 자동 검증

특히 Layer 4의 **“Deterministic Legal Consistency Checker”**는 공식 컴포넌트명이나 공개된 아키텍처가 아니라면 삭제해야 합니다. 생성된 인용을 데이터베이스와 대조한다고 해서 시스템 전체가 결정론적으로 법적 정확성을 보장하는 것은 아닙니다.

### E. “chain-of-thought verification” 표현은 부적절

외부 제품이 내부 chain-of-thought를 사용하거나 노출한다고 단정할 수 없습니다. 안전한 표현은 다음과 같습니다.

> “multi-step retrieval, tool use, citation checking, and iterative drafting”

### F. 출시 지역과 일정도 분리 검증 필요

- 미국 즉시 GA
- 캐나다·영국·호주 2026년 말 출시

이 일정이 공식 보도자료에 없다면 삭제해야 합니다. “planned expansion”과 확정된 출시 일정을 구분하십시오.

### 품질 보완

“Anthropic 플러그인 발표 후 주가 16% 하락”이 사실이라면 다음을 밝혀야 합니다.

- 종가 기준인지 장중 기준인지
- 정확한 거래일
- Anthropic 발표와의 인과관계가 언론 해석인지 회사 설명인지

주가 하락을 이번 통합이 “directly addresses”한다고 단정하기보다는 투자자 우려에 대응하는 전략으로 해석된다고 쓰는 편이 적절합니다.

# 4. Item 3 — Massachusetts AI 안전 법안

## 판정: **핵심 법률 사실을 재검증해야 하며 비교표에 오류 존재**

### A. 법안 번호와 조문이 없는 것이 가장 큰 문제

다음 핵심 주장을 검증하려면 최소한 아래 정보가 필요합니다.

- 경제개발 옴니버스 법안 번호
- 상원 수정안 또는 관련 섹션 번호
- 상원 통과일과 표결 결과
- 하원안과의 차이
- conference committee 또는 reconciliation 상태
- 감사 주체와 독립성 요건
- 정확한 적용 대상
- 시행일과 집행 기관

현재는 “Massachusetts Economic Development Omnibus Legislation”이라고만 되어 있어 **120일 주기·제3자 감사·공개 등록부**라는 세부사항을 원문 조문과 대조할 수 없습니다.

### B. “감사”, “평가”, “보고”를 구분해야 함

법안이 실제로 요구하는 것이 다음 중 무엇인지 확인해야 합니다.

- 독립 제3자 감사
- 개발자 자체 평가
- 외부 평가를 포함할 수 있는 위험 평가
- 안전 프레임워크 갱신
- 주 정부 보고
- 공개 요약문 제출

원문이 “risk assessment”라고 되어 있다면 이를 법적 의미가 더 강한 “independent audit”로 바꾸면 안 됩니다.

### C. “미국에서 가장 엄격한 법안”은 검증 가능한 사실보다 평가적 표현

“nation’s strictest”를 쓰려면 California, Colorado, New York 등 다른 주의 현행법 및 계류 법안과 다음 항목을 비교해야 합니다.

- 적용 임계치
- 감사 주기
- 공개 범위
- 집행 권한
- 민사책임
- 위반 시 제재

근거가 없다면 다음처럼 낮추는 것이 적절합니다.

> “미국 주정부 차원에서 상대적으로 강한 정기 평가 의무를 제안하는 법안”

### D. California SB 1047 비교표가 부정확

초안은 SB 1047을 다음처럼 묘사합니다.

> “Pre-deployment single assessment”

이는 지나치게 단순화됐습니다. SB 1047은 단 한 번의 사전 평가만을 요구하는 구조로 요약하기 어렵고, 안전·보안 프로토콜, 인증과 업데이트, 사고 보고 및 집행 수단 등을 포함했습니다.

또한:

> “Unified AI industry pushback”

도 정확하지 않습니다. 기업과 연구자들의 입장이 동일하지 않았고, Anthropic 등은 전면적인 단일 반대라기보다 조문 수정과 위험 기반 규제에 대해 보다 복합적인 입장을 보였습니다.

### E. “CBRN synthesis”, “algorithmic privilege escalation” 등은 조문 표현인지 확인 필요

법안이 실제로 열거한 위험 범주가 아니라 기자나 초안 작성자의 기술적 재분류라면, 조문의 직접적 요구인 것처럼 쓰면 안 됩니다. 원문 용어와 분석자의 해석을 분리해야 합니다.

### F. OpenAI와 Anthropic의 입장도 문서 근거 필요

다음 자료를 각각 연결해야 합니다.

- OpenAI의 서한 또는 공식 성명
- Anthropic의 서한·증언·정책 문서
- 주지사실과의 접촉을 입증하는 공개 기록 또는 직접 인용

Anthropic이 주정부와 대화했다는 사실만으로 해당 법안 전체를 지지하거나 RSP가 공식 법안 청사진으로 채택됐다고 단정할 수는 없습니다.

### 메타데이터 오류

`paradigm_shift_category: Architecture`는 법률·거버넌스 항목과 맞지 않습니다. `Governance`, `Regulation` 또는 `Policy`로 수정하는 것이 적절합니다.

# 5. Item 4 — Hot Interconnects 2026

## 판정: **시간 요건은 충족하지만 발표 제목 이상으로 기술 내용을 과도하게 확장**

### A. 시간 윈도우

이 항목은 `slot_category: 6`이고 `event_within_7d_window: true`이므로, 2026년 8월 20일 행사는 7일 예외 범위에 명백히 들어갑니다. **시간상 문제는 없습니다.**

### B. 프로그램 페이지는 발표 존재를 확인할 수 있지만 세부 성능을 입증하지 못함

제시된 URL:

```text
https://hoti.org/program/
```

이 URL은 학회 전체 프로그램을 확인하는 데에는 적합하지만 다음을 증명하기에는 부족합니다.

- KV-cache 중복 할당 40% 이상 감소
- 224G/448G SerDes 사용
- CPO 기반 특정 leaf-spine 구조
- CXL 메모리 스위치의 상용 통합 단계
- OCI, Open CPX, SDM4 MCF, XPO가 각 발표에서 실제로 다뤄졌다는 점

해당 수치와 기술은 슬라이드, 논문, 녹화 영상 또는 세션 초록에 직접 나와야 합니다.

### C. “모든 GPU가 가중치와 KV cache 복사본을 유지한다”는 일반화는 오류

초안:

> “each GPU to maintain its own duplicate copy of model weights and KV caches”

현대 대규모 추론 시스템은 tensor parallelism, pipeline parallelism, expert parallelism 등을 통해 모델 가중치를 GPU 간에 분할할 수 있습니다. KV cache도 요청 및 병렬화 방식에 따라 샤딩되거나 특정 워커에 배치됩니다.

정확한 표현:

> “일부 배치·복제 구성에서는 모델 및 KV-cache 배치로 인해 메모리 파편화와 유휴 용량이 발생할 수 있다.”

### D. CXL과 랙 간 광 네트워크를 하나의 캐시 일관성 계층처럼 묶어서는 안 됨

CXL은 기본적으로 PCIe 물리 계층을 기반으로 한 비교적 짧은 거리의 호스트·장치·메모리 연결 표준입니다. 광 링크나 fabric 확장 기술을 통해 범위를 넓히려는 연구·제품이 존재하더라도, 일반적인 CXL 스위치만으로 수십 개 랙에 걸친 저지연 캐시 일관성 메모리가 이미 구현되는 것처럼 설명하면 과장입니다.

다음 계층을 분리해야 합니다.

1. 서버 또는 랙 내부 CXL 메모리 확장·풀링
2. GPU scale-up fabric
3. 랙 간 Ethernet/InfiniBand scale-out network
4. CPO·광 I/O
5. 소프트웨어 기반 원격 KV-cache 계층

### E. “byte-addressable pooled memory”가 곧 실효 대역폭 향상은 아님

공유 메모리는 용량 활용률을 높일 수 있지만, HBM보다 지연시간이 크고 대역폭이 낮을 가능성이 높습니다. 초안은 이를 “effective cluster memory bandwidth utilization” 개선으로 단정합니다. 더 정확한 설명은 다음과 같습니다.

> “HBM 용량 압박과 메모리 파편화를 줄일 수 있지만, 접근 지연과 대역폭 계층화에 따른 성능 비용이 있다.”
