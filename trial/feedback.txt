## 3. Google HEIR 오픈소스 공개

### 판정: **핵심 이벤트 날짜 오류 + 기술적 과장**

### 명백한 사실 오류

HEIR는 2026년 8월에 처음 오픈소스로 공개된 신규 프로젝트가 아닙니다. `google/heir` 저장소와 Google의 HEIR 공개 활동은 **2026년보다 훨씬 이전부터 존재**했습니다. 따라서 다음 표현은 잘못됐습니다.

> “On August 14–16, 2026, Google announced the open-source release of HEIR”

2026년 8월에 특정 버전, 백엔드, 예제 또는 통합 기능이 새로 공개됐을 수는 있지만, 그러한 경우 이벤트는 **“HEIR 오픈소스 공개”가 아니라 해당 신규 릴리스**여야 합니다.

### 시간 오류

메타데이터가 `event_date: 2026-08-14`이므로 표준 24시간 윈도 밖입니다. 이 항목은 Category 6도 아니며 `ongoing_story_exception`도 false입니다.

GitHub에 8월 16일 커밋이 있었다는 것만으로는 일반적으로 “오픈소스 릴리스”라는 뉴스 이벤트가 성립하지 않습니다. 태그가 붙은 릴리스, 공식 블로그, 기능 발표가 필요합니다.

### 맞는 기술적 골격

다음 설명은 대체로 타당합니다.

- HEIR는 MLIR 기반 동형암호 컴파일러 인프라
- Apache-2.0 라이선스
- 암호화된 데이터를 복호화하지 않고 연산하는 HE/FHE 워크로드를 지원
- OpenFHE 등 암호 라이브러리와 연결되는 컴파일러 계층을 제공

### 기술적으로 잘못되거나 과장된 표현

#### 1. “zero-knowledge encrypted inference”

FHE와 영지식증명은 서로 다른 암호학적 개념입니다.

- **FHE:** 암호문 상태로 연산하여 데이터 기밀성을 보호
- **Zero-knowledge proof:** 어떤 명제가 참임을 내용 공개 없이 증명

HEIR가 FHE 추론을 지원한다고 해서 자동으로 “zero-knowledge inference”가 되지는 않습니다. 이 표현은 삭제해야 합니다.

#### 2. “표준 사전학습 모델을 자동으로 변환”

HEIR는 범용 PyTorch/JAX 모델을 아무 수정 없이 FHE 회로로 변환하는 완전 자동 제품으로 묘사하면 안 됩니다. 일반적으로 다음 제약이 있습니다.

- 지원 연산 집합
- 비선형 활성화 근사
- multiplicative depth
- ciphertext packing
- scale 및 noise 관리
- 부트스트래핑 비용

따라서 “표준 모델을 자동 변환”보다는 **“지원되는 연산과 프런트엔드 범위 내에서 암호 회로로 lowering한다”**가 정확합니다.

#### 3. “production applications”

사기 탐지·침입 탐지·DLRM·hotword detection이 예제나 데모였다면 “production applications”라고 부를 수 없습니다. 실제 운영 배치와 성능 수치가 제시되지 않았다면 **reference demos** 또는 **example workloads**로 수정해야 합니다.

#### 4. “1,000~10,000배 느림”

FHE 오버헤드는 스킴, 보안 파라미터, 모델, 배치 크기, 하드웨어에 따라 크게 달라집니다. 단일 범위를 일반 법칙처럼 제시하려면 직접적인 벤치마크 출처가 필요합니다.

#### 5. “subpoena exposure 해소”

FHE는 서버가 평문을 직접 보지 않게 할 수 있지만, 키 관리·메타데이터·입출력 단·법률적 데이터 제출 의무까지 자동으로 제거하지는 않습니다.

### 권고

이 항목은 다음처럼 재구성해야 합니다.

> “Google HEIR 프로젝트가 2026년 8월 16일에 새로 추가한 ○○ 백엔드/프런트엔드/최적화 기능”

그러한 신규 개발이 없다면 이번 24시간 브리핑에서 제외해야 합니다.

## 4. Alphabet `Frozen v2` 맞춤형 칩

### 판정: **시간상 적격이나, 핵심 제품과 사양을 신뢰할 만한 출처로 검증할 수 없음**

### 시간 판정

8월 16일 공개라면 표준 24시간 윈도 내입니다. Category 6이므로 이벤트가 7일 이내였다면 별도 허용도 가능합니다.

### 출처 문제

Primary URL은:

`https://www.tmcnet.com/topics/articles/2026/08/16/alphabet-develops-frozen-v2-chip-cut-gemini-inference.htm`

그러나 출처 표기에는 `TMC Insight`라고 되어 있고 실제 도메인은 `TMCnet`입니다. 출처 이름부터 일치시키는 것이 필요합니다.

더 중요한 문제는 TMCnet이 Alphabet의 공식 실리콘 로드맵 자료가 아니라는 점입니다. 다음과 같은 비공개 제품 사양을 단일 2차 기사로 확정해서는 안 됩니다.

- `Frozen v2`라는 공식 코드명
- 2028년 초기 데이터센터 배치
- Gemini 그래프의 물리적 하드와이어링
- multi-head latent attention 경로
- 6~10배 tokens/W
- sub-2nm
- on-chip SRAM/eDRAM
- `TPU 8i / 8t`
- v5e 대비 2.5배 효율

Tom’s Hardware, The Information, Semiconductor Engineering이 실제로 이를 독립 보도했다면 **각 기사 URL과 원출처의 동일 인용문**을 제공해야 합니다. 단순히 매체 이름만 나열한 것은 교차 검증이 아닙니다.

### 아키텍처 설명의 문제

#### 1. “Gemini 그래프를 직접 논리 게이트로 변환”

고정 기능 블록을 늘리는 것과 특정 학습된 모델의 전체 계산 그래프·가중치를 물리적 논리 게이트로 굳히는 것은 다릅니다. 초안은 양자를 혼동합니다.

최소한 다음을 구분해야 합니다.

- 특정 연산 패턴용 fixed-function datapath
- attention/KV-cache용 특화 유닛
- 모델 아키텍처 특화 명령 또는 데이터플로
- 학습된 가중치 자체를 ROM/논리에 고정
- 전체 모델 그래프의 완전한 하드와이어링

현재 설명은 가장 강한 형태인 “모델 전체를 실리콘에 새긴다”고 단정하지만, 이를 입증하는 회로 블록도나 특허·논문·공식 발표가 없습니다.

#### 2. `multi-head latent attention`

MLA는 특정 모델 계열과 강하게 연관된 구체적 아키텍처 용어입니다. Gemini가 해당 구조를 사용한다는 공식 기술 자료 없이 Frozen v2의 고정 기능 블록으로 단정하면 안 됩니다.

#### 3. 메모리 이동 “제거”

고정 기능 ASIC도 가중치, 활성값, KV 캐시, 칩 간 통신이 필요합니다. 데이터 이동을 줄일 수는 있지만 **memory-to-compute transfer overhead를 제거한다**는 표현은 물리적으로 과도합니다.

#### 4. 패키지·전력 설계 효과

다음 내용은 실제 floorplan과 전력 모델 없이 확정할 수 없습니다.

- transient switching noise가 크게 감소
- 소켓 열 방출이 감소
- PDN이 단순화
- instruction pipeline 제거 면적을 eDRAM으로 재할당

고정 기능 설계는 오히려 국부적 전력 밀도와 hotspot을 높일 수도 있습니다.

### 로드맵 표 문제

- TPU v5e와 Ironwood는 동일 세대 또는 동일 기간의 단일 아키텍처가 아닙니다.
- Ironwood는 공개적으로 알려진 TPU 세대 구분을 명확히 반영해 별도 행으로 작성해야 합니다.
- `TPU 8i/8t`, 3nm, 2.5배 tokens/W, Frozen v2의 sub-2nm는 공식 근거가 없으면 삭제해야 합니다.
- `current TPUs`가 어느 세대를 의미하는지 불분명하므로 6~10배 비교의 기준점도 검증 불가능합니다.

### 권고

공식 Alphabet/Google Cloud 발표, 특허, 학회 발표, 공급망 당사자 발언 또는 최소 2개의 독립적이고 신뢰도 높은 보도가 확보되기 전에는:

> “Alphabet이 Frozen v2를 개발한다”

가 아니라

> “TMCnet이 출처 불명의 정보를 인용해 이른바 ‘Frozen v2’를 보도했다”

정도로 낮춰 써야 합니다. 현재 상태에서는 브리핑 본문보다 **미확인 루머 섹션**이 적절합니다.
