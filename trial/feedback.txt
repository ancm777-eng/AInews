### ① Remotion Claude Code 플러그인

**판정: 주제 유지 가능. 신규 출시일·성능 수치 확인과 렌더링 설명 수정 필요.**

#### 확인이 필요한 핵심 사항
- 제시된 공식 도메인의 문서가 존재하는지와 **11월 5일 신규 출시를 입증하는지**는 별개입니다. 릴리스 노트·공식 공지·저장소 릴리스 등 날짜가 있는 자료가 필요합니다.
- `/remotion:remotion-create`, `remotion-dev/claude-code-plugin`, CLI·Desktop 지원, Anthropic 디렉터리 등록 여부를 각각 확인해야 합니다.
- **Claude Opus 5.5·Sonnet 5.5**라는 정확한 모델명과 해당 통합에서의 사용 가능 여부는 Anthropic 자료로 확인해야 합니다.
- “일반 노트북에서 120초 이내”는 기기·장면 복잡도·해상도·병렬도·코드 수정 횟수가 없는 성능 주장입니다. 벤치마크 출처를 붙이거나 삭제하십시오.

#### 기술적 수정
- **“Playwright 같은 헤드리스 브라우저”는 분류가 부정확합니다.** Playwright와 Puppeteer는 브라우저 자동화 도구이고 Chromium이 브라우저입니다. Remotion이 실제로 사용하는 구현도 확인해야 합니다.
- 프레임 단위로 시간을 제어하는 Remotion 파이프라인을 일반적인 **CSS keyframes의 실시간 재생**과 동일하게 설명하면 오해를 낳습니다. 프레임 번호 기반 애니메이션과의 관계를 명시하십시오.
- **“zero pixel-level hallucination”, “pixel-perfect”는 보장 표현으로 부적절합니다.** 확산 모델의 생성 아티팩트를 피할 수 있어도, 에이전트의 코드 오류·폰트 차이·난수·브라우저 및 GPU 차이에 따른 결과 변동까지 없어지는 것은 아닙니다.
- After Effects는 엄밀히 말해 NLE보다는 **모션 그래픽·합성 도구**입니다. 또한 스크립팅·자동화·배치 렌더링이 가능하므로 비교표의 “수동이어서 확장성 낮음”은 지나친 일반화입니다.
- Three.js·WebGL을 사용하는 작업까지 포괄하면서 “GPU에서 CPU로 이동”한다고 단정하지 마십시오. **작업에 따라 GPU 의존도를 줄일 수 있다**는 수준이 적절합니다.

**중개 경로의 공급 가격과 개발사 직접 API 가격을 분리해 표기해야 합니다.** `0731`이라는 접미사 자체도 11월 5일 출시를 반증하지는 않지만, 체크포인트 날짜와 공급자 등록일이 다른지 확인할 필요가 있습니다.

#### 확인 가능한 수치 문제
- `$1.04 → $0.41`의 비용 감소율은 **약 60.6%**입니다.
- 따라서 이 수치만으로 “70~80% 비용 절감”을 뒷받침할 수 없습니다.
- 표의 `$1.10~$1.85`와 비교하면 약 **62.7~77.8%** 감소입니다. 비교 대상과 산식을 명시해야 합니다.

#### 기술·벤치마크 보완

- 92~132 tokens/s는 GPU·병렬도·입출력 길이·배치 크기를 제시해야 비교 가능합니다.
- 1M 컨텍스트 지원은 **1M 토큰에서의 추론 품질이나 도구 호출 안정성을 보증하지 않습니다.**

### ④ AMD Hierarchical Data Pipelining

**판정: 7일 예외 적용 대상. 논문 서지사항·성능 지표 정의·배포 상태 확인 필요.**

#### 출처·상태 확인
`arxiv.org/abs/2611.05751`의 실제 제목·저자·소속·최초 제출일·버전 이력을 확인해야 합니다. **arXiv 등록 자체는 동료심사 완료를 의미하지 않습니다.** 별도의 학회·저널 게재 근거가 없다면 “peer-reviewed” 표기는 빼야 합니다.

또한 논문에서 구현·평가한 것과 **ROCm 정식 라이브러리에 병합·배포된 것**은 다릅니다. “fully integrated”, “open-source release verified”에는 저장소·PR·릴리스 버전이 필요합니다.

#### 명확한 내부 모순·기술적 오류
- 개요에서는 **“최대 1.88배”**, 기술 설명에서는 **“평균 1.88배”**라고 합니다. 같은 수치의 통계 정의가 다르므로 원문에 맞춰 통일해야 합니다.
- **LDS와 레지스터 파일은 별개 자원입니다.** LDS 사용량 증가는 CU에 상주 가능한 작업 그룹 수와 점유율을 제한할 수 있지만, “다른 스레드 블록의 레지스터 공간을 줄인다”는 직접 설명은 부정확합니다.
- 커널·통신 중첩 실험의 가속률을 **전체 학습 처리량·MFU·TCO 개선율**로 그대로 확대하면 안 됩니다.
- “MFU 70% 이상에 필수”, “메모리 기아 제거”, “zero-stall”, “전력 강하 제거”, “추가 전력 없이 FLOPS 20~35% 개선”은 별도의 시스템·전력 측정 근거가 필요합니다.
- 과거 GPU 통신을 모두 동기·블로킹 방식으로 묘사한 비교표는 비동기 복사와 통신·연산 중첩이라는 기존 기법을 누락합니다.
