## 1. KST 시간 윈도우

검증 기준 시각은 **2026년 11월 10일 12:48 KST**입니다.

| 적용 대상 | 허용 기간 |
|---|---|
| 기사 1·2·3: 최근 24시간 | **11월 9일 12:48~11월 10일 12:48 KST** |
| 기사 4: `slot_category: 6`, 최근 7일 | **11월 3일 12:48~11월 10일 12:48 KST** |

- **기사 1·2·3:** `2026-11-09`라는 날짜만으로는 24시간 충족 여부가 확정되지 않습니다. 실제 사건이 **11월 9일 12:48 KST 이후** 발생했는지 확인해야 합니다. 현재의 `event_within_24h_window: true`는 검증 근거가 부족합니다.
- **기사 4:** 기재된 사건일이 맞다면 **7일 예외에 부합**합니다. 24시간 밖이라는 이유만으로 교체할 필요는 없습니다.
- **Hugging Face Daily Papers 등재일과 연구 최초 공개일은 구분해야 합니다.** 기존 논문의 단순 등재라면 새로운 연구 발표일로 취급할 수 없습니다. 기사 2·4는 arXiv 최초 제출·버전 갱신·코드 공개 시각 중 실제로 보도하는 사건을 명시해야 합니다.

**현재 자료로 확인된 시간 위반은 없지만, 기사 1~3의 시간 적합성도 아직 확정되지 않았습니다.**

## 2. 기사별 사실관계 검토

### 기사 1 — LongBanana

**판정: 주제는 적합하나, 수치와 모델 비교를 보완해야 합니다.**

이미지 생성·편집 및 에이전트형 크리에이티브 도구는 유효한 브리핑 주제입니다. 다만 다음을 수정해야 합니다.

- **벤치마크 입력 규모와 모델 수용 능력을 혼동하고 있습니다.** 과제당 평균 32개의 참조 이미지가 있다는 사실은, 모델이 32개를 동시에 입력받거나 정확하게 활용한다는 뜻이 아닙니다. 이를 곧바로 “참조 용량 +700%”로 표현하면 안 됩니다.
- **“기존 모델 한계 3~4장”, “Nano Banana/GPT-Image 최대 3~5장”은 버전·API·평가 조건 없이 일반화할 수 없습니다.** 제품별 입력 제한과 실제 다중 객체 준수 성능도 서로 다른 지표입니다.
- **“단일 패스 모델로는 해결할 수 없음”은 실험상 성능 부족보다 강한 결론**입니다. “해당 평가에서 에이전트 방식이 더 높은 성능을 보였다”로 낮추는 것이 타당합니다.
- **GPU 연산량 4~8배**, **80% 초과 실패율**, **Graph-RAG**, **RPR의 정확한 정의**는 논문 표·절 또는 코드 근거가 필요합니다.
- 4,670개 평가 항목을 90개 과제로 나누면 약 **51.9개/과제**입니다. “약 50개 체크리스트”와는 산술적으로 모순되지 않습니다.

**원문 확인 필요:** Kuaishou/Kolors 소속, arXiv ID와 제목의 일치, 89.4%·κ=0.83의 평가 방식, 공개 GitHub·Hugging Face 저장소. 현재 기재된 링크를 실제로 열어 확인한 상태는 아닙니다.

### 기사 2 — EvoWorld

**판정: 연구 주제는 적합하나, 아키텍처 설명과 성능 주장이 과도합니다.**

- **`Computer Vision and Pattern Recognition Consortium`은 저자 소속이나 발행기관이 식별되는 출처 표기가 아닙니다.** 논문 저자·대학·기업·연구실의 정식 명칭으로 교체해야 합니다.
- **“확산 아키텍처에는 지속 메모리가 없다”는 설명은 범위가 지나치게 넓습니다.** 구체적인 비교 모델과 조건에 한정해야 합니다.
- **지속 상태 토큰이 있다는 사실만으로 “임의 길이의 시간 지평”이 입증되지는 않습니다.** 상태 누락·압축·오차 누적과 최대 평가 길이를 함께 제시해야 합니다.
- **120개 사례**, **기존 모델 실패율 65% 초과**, **기존 시간창 8~16초**는 각각 출처와 평가 정의가 필요합니다.
- 중간 계층의 **기호 상태 벡터·바운딩 좌표·잠재 제어 신호**가 실제 구현인지 확인해야 합니다. 개념적 해석이라면 논문이 구현한 사실처럼 쓰면 안 됩니다.
- **순차 의존성이 실시간 스트리밍을 불가능하게 만든다는 결론은 성립하지 않습니다.** 업데이트 주기, 처리 지연, 파이프라이닝에 따라 달라집니다. “실시간 구현의 지연 부담을 높인다”가 적절합니다.

제목의 **“Solves Temporal Amnesia”** 역시 전체 문제 해결이 아니라 **“평가한 비가시 인과 일관성을 개선”**하는 수준으로 조정하는 편이 안전합니다.

### 기사 3 — AMD·Google Cloud TPU 8tx

**판정: 가장 큰 수정이 필요한 항목입니다. 하드웨어 사양 오류와 보안 범위의 비약이 있습니다.**

#### 확정적으로 수정할 부분

1. **5세대 EPYC와 PCIe Gen6를 연결한 도식은 잘못됐습니다.**  
   5세대 EPYC 9005 플랫폼의 CPU 측 지원은 **PCIe 5.0 및 CXL 2.0**입니다. 별도 브리지나 다른 플랫폼을 명시하지 않는 한, EPYC 호스트 연결을 PCIe Gen6로 표시하면 안 됩니다.

2. **“Zen 5, 소켓당 192코어”는 코어 유형 구분이 필요합니다.**  
   5세대 EPYC의 **192코어 구성은 Zen 5c 기반 고밀도 제품**입니다. 일반 Zen 5 기반 제품과 구분하여 “Zen 5/Zen 5c, SKU별 상이”로 적어야 합니다. 실제 TPU 호스트 SKU가 공개되지 않았다면 최대 사양을 탑재 사양처럼 제시해서도 안 됩니다.

#### 보안상 성립하지 않는 추론

- **EPYC의 SEV-SNP 적용만으로 TPU 메모리·연산·인터커넥트까지 종단간 보호된다는 결론은 나오지 않습니다.**  
  SEV-SNP의 호스트 VM 보호와 가속기 측 보호는 구분해야 합니다. TPU 메모리 보호, 호스트–TPU 전송, 장치 인증·증명, 키 관리의 별도 근거가 필요합니다.
- **“광학 인터커넥트”는 “암호화된 인터커넥트”의 동의어가 아닙니다.** Boardfly의 존재·구조와 통신 암호화 여부를 각각 검증해야 합니다.

#### 반드시 원문으로 확인할 핵심

- TPU **8tx/8t**의 공식 명칭 및 비교 관계
- AMD 보도자료의 실제 존재와 발표 시각
- **최대 2배 지연 개선**, **거의 0인 보안 오버헤드**의 워크로드·기준선
- 전 지역 또는 일부 지역의 **정식 서비스 여부**
- “업계 최초”와 과거 오버헤드 **15~25%/15~28%**의 근거

이 항목은 제목부터 본문까지 **“종단간 confidential AI 배포”가 핵심 주장**입니다. 공식 발표가 호스트 CPU 채택만 확인한다면, 해당 보안 주장은 삭제하고 기사를 CPU 채택 중심으로 다시 써야 합니다. 공식 발표 자체나 핵심 제품명이 부정확하다면 그때는 교체 대상입니다.

### 기사 4 — PCBRouteAgent

**판정: 7일 예외에 적합한 주제이나, 구현·평가 범위의 구분이 필요합니다.**

- **“Peer-reviewed technical preprint”는 심사·채택 근거가 있어야 합니다.** arXiv 게시만으로 동료심사가 입증되지는 않습니다. 학회·저널 정보가 없으면 “연구 프리프린트”로 수정하십시오.
- **KiCad Python API 사용과 네이티브 push-and-shove 라우터의 자동 제어는 별개입니다.** 플러그인, 수정 빌드, IPC, UI 자동화 등 실제 연결 방식을 제시해야 합니다.
- **FreeRouting을 “글로벌 계획 없는 탐욕적 최단 경로”로만 묘사한 것은 부정확한 축약**입니다. 비교 대상 버전·설정·실험 결과로 평가해야 합니다.
- **DRC 통과는 제조 완료나 SI/PI 검증 완료를 뜻하지 않습니다.** 도식의 `Clean Fabricated Board`는 `DRC-clean routed layout` 등으로 바꾸십시오.
- D3-C의 40% 결과만으로 실패 원인을 BGA 팬아웃·임피던스 제어라고 단정할 수 없습니다. 논문의 실패 분석에 근거해야 합니다.

**수치 계산 자체는 맞습니다.**
- 94.9−58.9 = **36.0%p**
- 100.0−86.1 = **13.9%p**
- 40.0−30.0 = **10.0%p**

다만 247개 보드, 분할 구성, 각 분모와 성공 정의는 원문 확인이 필요합니다. **D2·D3-B에서 100%**라는 결과를 일반적인 “DRC 준수율 100%”로 확대하지 마십시오.

## 3. 요약·일정표 보완

- **“업계 표준으로 정착”, “확산 모델만으로는 불가능”, “연산량이 한 자릿수 배 이상 증가”**는 제시된 사례들만으로 입증되지 않습니다. 연구 결과와 전략적 전망을 구분해야 합니다.
- 호스트 CPU·인터커넥트의 중요성은 타당한 분석 주제지만, **기사 3의 검증되지 않은 보안·성능 수치를 근거로 결론을 확정하면 안 됩니다.**
- 상용 EDA의 기존 API 유무와 새 에이전트 인터페이스 발표 여부를 구분하십시오.
- 행사 일정은 공식 행사별 URL이 없어 검증되지 않았습니다. **Ignite·NeurIPS·IEDM·DesignCon·ISSCC의 날짜·장소와 편집자가 예상한 의제를 별도로 확인**해야 합니다.
