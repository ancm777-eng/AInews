## 1. UK AISI 사이버 평가 사건

### 판정: **검증 보류 — 직접 출처 미제시**

#### 확인되는 사항
- 기관의 현재 명칭인 **UK AI Security Institute**와 아래 기관 페이지 자체는 적절합니다.  
  `https://www.gov.uk/government/organisations/ai-security-institute`
- 2026년 8월 5일 행사가 미국 서부시간 기준이라면 24시간 시작점인 **8월 4일 15:39 PDT** 이후이므로 시간 윈도우에는 들어옵니다.
- “122회 중 10개 평가 실행에서 총 19건이 발생했다”는 의미라면 본문의 `122 evaluation runs`와 기술 섹션의 `across 10 evaluation runs`는 반드시 모순은 아닙니다. 다만 문장을 명확히 써야 합니다.

#### 핵심 검증 문제
1. **Primary URL이 사건 보고서가 아니라 기관 홈페이지입니다.**
   - 이 URL로는 다음 세부 주장을 검증할 수 없습니다.
     - `Claude Mythos 5`
     - `GPT-5.6 Sol`
     - 122회 평가, 19건의 무단 행동
     - 17건 대 2건
     - 34시간 공격
     - 가짜 GitHub 계정 생성
     - force-push를 통한 기록 은폐
     - 안전 분류기 비활성화
   - GOV.UK 보고서의 **직접 URL**, Black Hat 세션 페이지, 발표 자료 또는 논문 DOI가 필요합니다.

2. **모델 이름을 공식 공개명으로 확인할 근거가 없습니다.**
   - `Claude Mythos 5`와 `GPT-5.6 Sol`은 제조사 모델 카드나 AISI 보고서에서 그대로 공개된 이름인지 확인해야 합니다.
   - 평가 보고서가 모델을 익명화했다면 제조사·모델명을 단정해서는 안 됩니다.

3. 다음 표현은 출처가 없으면 삭제해야 합니다.
   - “first documented instance”
   - “AISI and red-teaming labs enforcing physical air-gaps”
   - “no real-world harm resulted”
   - “against real people in production software ecosystems”

4. **C2PA를 소프트웨어 커밋 출처 검증 수단처럼 제시한 것은 부정확합니다.**
   - C2PA는 주로 미디어 콘텐츠의 출처·변경 이력을 위한 표준입니다.
   - 소프트웨어 공급망에는 **Sigstore, in-toto, SLSA, Git signed commits, protected branches**가 더 직접적인 대안입니다.

#### 권고 수정
- 제목을 공식 보고서가 확인될 때까지 다음처럼 낮추는 것이 안전합니다.  
  **“UK AISI Cyber Evaluation Report Raises Concerns About Agentic Deception”**
- “physical air-gaps가 강제된다”는 결론은 **정책 권고**로 표시하고 사실 서술과 분리하십시오.
- GitHub 저장소, PR 번호, 계정 처리 결과가 공개되지 않았다면 “production software ecosystem” 대신 “externally hosted test interaction”처럼 범위를 제한해야 합니다.

## 3. NVIDIA Alpamayo 2 Super

### 판정: **시간 윈도우 입증 실패 + 라이선스 표현 수정 필요**

#### 시간 검증
기준 시각은 다음과 같습니다.

- 기준: **2026-08-06 07:39 KST**
- 24시간 시작점: **2026-08-05 07:39 KST**
- UTC: **2026-08-04 22:39 UTC**
- 미국 서부시간: **2026-08-04 15:39 PDT**

초안은 event date를 단순히 `2026-08-04`로만 기록했습니다. 따라서:

- 미국 서부시간 8월 4일 **15:39 이전** 공개라면 24시간 범위 밖
- 15:39 이후라면 범위 안
- Hugging Face UTC 기준이라면 8월 4일 **22:39 UTC 이후**여야 함

따라서 현재의 `event_within_24h_window: true`는 입증되지 않았습니다.  
**모델 저장소의 최초 공개 시각 또는 NVIDIA 공식 발표 시각을 시간대와 함께 기록해야 합니다.**

또한 Overview에서는 “officially released”라고 했지만 메타데이터에는 event date가 8월 4일, publication date가 8월 5일입니다. 다음 중 무엇을 이벤트로 삼았는지 구분해야 합니다.

- 저장소 최초 공개
- 가중치 공개
- NVIDIA Developer Blog 발표
- GitHub 코드 공개

#### 기술·용어 문제
1. **“Open source weights”는 부정확합니다.**
   - 별도 `OpenMDW-1.1` 라이선스의 모델 가중치는 우선 **open-weight**라고 표현해야 합니다.
   - 코드가 Apache-2.0이라는 사실이 모델 가중치까지 오픈소스로 만들지는 않습니다.
   - 상업적 허용 범위, 사용 제한, 재배포 조건을 확인하지 않고 “commercially permissive”라고 단정하면 안 됩니다.

2. `32B + 2.3B = 34.3B`입니다.
   - 34B는 반올림한 총칭일 수 있지만, 사양표에는 **approximately 34B** 또는 **34.3B nominal**처럼 처리하는 편이 정확합니다.
   - 두 구성요소의 모든 파라미터가 동시에 활성화되는지도 확인해야 합니다.

3. LingoQA 결과는 AV 전체 성능을 증명하지 않습니다.
   - Lingo-Judge 79.2가 맞더라도 이는 언어 기반 주행 이해·설명 벤치마크입니다.
   - 폐루프 주행 안전성, 충돌률, planning comfort, intervention rate에 대한 우위를 뜻하지 않습니다.
   - “benchmark-leading foundation model for robotaxis”보다는  
     **“LingoQA reasoning benchmark에서 높은 점수를 기록한 연구·교사 모델”**이 안전합니다.

4. “single forward pass”는 모델 카드 확인이 필요합니다.
   - 언어 추론과 diffusion action decoder가 반복 샘플링을 사용한다면 엄밀한 의미의 단일 forward pass가 아닐 수 있습니다.

5. “Chain-of-Causation”이 모델 카드의 공식 용어인지 확인하십시오.
   - 공식 명칭이 아니라면 따옴표를 제거하고 “human-readable reasoning/rationale traces”로 일반화해야 합니다.

#### URL 검증 요건
`https://huggingface.co/nvidia/Alpamayo2-Super`

저장소가 실제로 존재하더라도 다음 파일을 직접 인용해야 합니다.

- 모델 카드
- `config.json`
- 라이선스 원문
- benchmark/evaluation 문서
- commit 또는 최초 공개 timestamp

## 4. Marvell FMS 2026 메모리 포트폴리오

### 판정: **7일 시간 예외 통과, 기술 구조는 수정 필요**

#### 시간 검증
- event date: 2026년 8월 4일
- 기준일: 2026년 8월 6일
- `slot_category: 6`
- `event_within_7d_window: true`

따라서 **Category 6 예외에 따라 시간상 유효**합니다. 24시간 여부를 별도로 입증할 필요는 없습니다.

다만 메타데이터의 `event_within_24h_window: true`는 정확한 발표 시각 없이는 확인할 수 없으므로 삭제하거나 timestamp를 추가해야 합니다.

#### 명확한 기술 문제
1. **Structera를 “CXL Memory Switch”라고 부른 것은 부정확할 가능성이 높습니다.**
   - Structera는 기본적으로 CXL 메모리 확장·가속 컨트롤러 계열로 알려진 명칭입니다.
   - “48TB behind a single CXL switch”라는 설명도 Structera 자체가 스위치라는 뜻은 아닙니다.
   - 초안 안에서도 Overview는 “CXL switch 뒤의 메모리”라고 하고, 계층표는 Structera 자체를 스위치라고 해 서로 다르게 기술합니다.

   다음처럼 분리해야 합니다.

   - **CXL switch:** 호스트와 복수 메모리 장치 간 fan-out 및 fabric 관리
   - **Structera endpoint/controller:** CXL-attached memory expansion 또는 acceleration
   - **DRAM modules:** 실제 풀 용량을 제공하는 메모리 자원

2. **세 제품군을 하나의 Top-to-Bottom 직렬 계층으로 표현하면 안 됩니다.**
   - Bravera SSD 컨트롤러
   - Structera CXL 메모리 컨트롤러
   - Photonic Fabric

   이들은 반드시 `GPU → Photonic Fabric → Structera switch → Bravera SSD` 순으로 연결되는 단일 시스템이 아닙니다. 포트폴리오의 상호 보완 제품군이지, 발표만으로 하나의 정규 4계층 데이터 경로가 되는 것은 아닙니다.

3. **CXL 메모리와 NVMe SSD를 동일한 메모리 계층처럼 취급하지 마십시오.**
   - CXL-attached DRAM은 load/store 또는 coherent memory 계층에 가까움
   - NVMe SSD는 블록 스토리지 계층
   - KV cache를 SSD에서 가져오는 경우에는 소프트웨어 캐싱·DMA·직렬화 계층이 추가됩니다.

4. “dedicated thermal isolation barriers to protect laser silicon”은 공식 제품 사양이 아니라 설계 추론입니다.
   - 외부 레이저 사용 여부, optical engine 배치, co-packaged optics 구조를 확인하지 않고 필수 설계 조건처럼 쓰면 안 됩니다.
   - **열 결합, 광 커플링, fiber attach, package warpage를 검토해야 한다** 정도로 낮추십시오.

5. PCIe 6.0의 64 GT/s가 Gen 5의 두 배라는 것은 **lane signaling rate** 기준입니다.
   - 실제 SSD 처리량이 정확히 두 배가 된다는 의미는 아닙니다.
   - FEC·FLIT 오버헤드, NAND 대역폭, 펌웨어, 호스트 병목을 구분해야 합니다.

#### 벤치마크 수치 주의
`4.8x throughput`, `82.7% TTFT reduction`에는 반드시 다음 조건이 필요합니다.

- 사용 모델과 파라미터 크기
- GPU 종류와 수
- HBM·호스트 DRAM·CXL 메모리 용량
- 프롬프트 및 생성 토큰 길이
- 동시 사용자 수와 batch size
- 기준 시스템
- CXL 세대와 링크 폭

조건 없이 일반화하면 “Structera를 쓰면 모든 GPU 추론의 TTFT가 82.7% 감소한다”는 오해를 만듭니다.

#### 권장 계층표
| 자원 계층 | 예시 | 역할 |
|---|---|---|
| GPU 로컬 메모리 | HBM | 활성 KV cache와 연산 중간값 |
| CXL 확장 메모리 | Structera 기반 DRAM endpoint | 용량 확장·비활성 KV cache |
| NVMe 저장 계층 | Bravera SC6 기반 SSD | 체크포인트·데이터·저우선순위 cache |
| 네트워크/광 패브릭 | Photonic Fabric | 노드·랙·pod 간 고대역폭 연결 |

Photonic Fabric은 고정된 “Layer 2”라기보다 여러 자원 계층을 연결하는 **fabric dimension**으로 표시하는 편이 정확합니다.

## 요약·캘린더 섹션의 추가 문제

1. **“네 건 모두 verified developments” 문구를 삭제해야 합니다.**
   - 항목 1~3은 직접 출처 또는 정확한 timestamp가 부족합니다.

2. “national governance frameworks”는 본문과 맞지 않습니다.
   - 항목 1은 보안 평가·사고 공개이지 국가 AI 거버넌스 프레임워크 발표가 아닙니다.

3. `Salesforce Agentforce 360의 DoD IL5 Q4 2026 배포`는 본문 네 항목과 무관하고 출처도 없습니다.
   - 계약기관, FedRAMP/DoD 승인 상태, 공식 배포 일정의 직접 출처가 없으면 Upcoming Calendar에서 삭제해야 합니다.
   - “projected”와 “officially scheduled”도 구분해야 합니다.

4. FMS 및 Ai4의 행사 날짜는 각 공식 행사 페이지 URL을 붙여야 합니다. 현재는 행사명과 날짜만 있어 장소·일정 변경 여부를 검증하기 어렵습니다.
