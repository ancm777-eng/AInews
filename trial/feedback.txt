## Item 2 — Core Scientific·AMD, 500MW/최대 2.5GW

### 판정: **핵심 발표 확인을 전제로 조건부 통과, 계약 의미는 하향 조정 필요**

회사명과 기술 스택의 조합 자체에는 명확한 논리적 모순이 없습니다.

또한 Mathew Hein을 AMD의 전략 담당 임원으로 지칭하는 것도 대체로 자연스럽습니다. 다만 다음 부분은 원문의 계약 용어를 정확히 옮겨야 합니다.

### 1) “최대 2.5GW 확보”는 옵션일 수 있음
초안에는 다음 표현이 혼재합니다.

- “secures”
- “guaranteed infrastructure pipeline”
- “contractual options to scale”
- “maximum expandable capacity”

`500MW committed`와 `option up to 2.5GW`는 전혀 다른 경제적 의미입니다. 후자가 옵션이라면 2.5GW 전체가 다음 조건을 충족한 것이 아닙니다.

- 확정 임대
- 전력 계통연계 확보
- 건설 금융 확정
- 환경·지방정부 허가 완료
- 실제 전력 공급 보장

권장 제목:

> “Core Scientific·AMD, 초기 500MW 협력 및 최대 2.5GW 확대 옵션 발표”

“AMD가 2.5GW를 확보했다”는 제목은 공식 원문이 확정 약정이라고 명시하지 않는 한 피해야 합니다.

`operational capacity beginning in 2027`은 현재 운영 중인 용량이 아니라 **2027년 가동 예정 용량**일 수 있습니다. 다음을 구분해야 합니다.

- 현재 energized capacity
- 개발 중인 capacity
- 계약된 capacity
- 옵션이 설정된 capacity
- 2027년 commissioning 목표

### 3) AMD 고객에게 제공되는지 확인 필요
AMD가 직접 데이터센터 용량을 쓰는 계약인지, AMD 고객을 Core Scientific과 연결하는 생태계 협약인지, 또는 공동 영업·설계 프레임워크인지 불명확합니다. 초안의 “AMD가 고객을 위해 보장된 인프라 파이프라인을 확보했다”는 서술은 계약 구조 확인 없이는 단정하기 어렵습니다.

### 4) 기술 표현 보완
- “isolated server racks”는 구체적 의미가 불명확합니다.
- “liquid-to-liquid cooling” 적용이 공식 발표에 명시됐는지 확인해야 합니다.
- “6th Gen EPYC”가 특정 배치 시점의 확정 제품인지, 포괄적 로드맵 언급인지 구분해야 합니다.
- ROCm은 시설이 직접 “호스팅”하는 물리 규격이 아니라 소프트웨어 생태계이므로, 전력·냉각 공동 설계와 같은 수준의 시설 사양으로 나열하면 안 됩니다.

현재 전략 분석은 계약 규모를 투자 의견으로 곧바로 확대하고 있습니다.

## Item 3 — MCP 2026-07-28 최종 사양

### 판정: **공식 사양 원문 확인 전에는 보류; 여러 기술 표현이 과도하거나 부정확**

### 1) “완전한 stateless protocol core”는 엄밀히 설명해야 함
MCP에서 다음은 별개의 상태입니다.

- HTTP 전송 계층의 세션 상태
- 프로토콜 초기화 및 capability negotiation
- 인증 토큰 상태
- 장기 실행 Task의 서버 측 상태
- 서버가 유지하는 리소스·작업 결과 상태

따라서 전송 계층이 stateless해졌다고 해서 MCP 전체가 상태를 보유하지 않는 것은 아닙니다. 특히 초안은 동시에 **Tasks를 통한 비동기 장기 작업**을 강조합니다. Task 자체는 식별자, 상태, 결과 또는 만료 정보를 서버 측에 보유할 수 있으므로 다음 표현은 과도합니다.

> “fully stateless protocol core eliminating session handshakes and shared session memory stores”

공식 사양이 정확히 무엇을 없앴는지 구분해야 합니다.

### 2) MCP Apps는 “서버가 UI를 직접 렌더링”한다고 표현하면 부정확
일반적으로 이런 앱 확장 구조에서는 서버가 UI 리소스나 메타데이터를 제공하고, **클라이언트/호스트가 보안 샌드박스 안에서 렌더링**합니다.

따라서:

> “server-rendered interactive UIs”

보다 다음이 안전합니다.

> “서버가 제공한 앱/UI 리소스를 MCP 호스트가 격리된 환경에서 렌더링”

### 3) OAuth와 OIDC를 동일한 보안 표준처럼 묶음
- OAuth 2.x: 권한 위임 및 액세스 토큰 프레임워크
- OIDC: OAuth 기반 신원 인증 계층

사양이 OIDC를 반드시 요구하는지, OAuth authorization server metadata나 protected resource metadata만 규정하는지 구분해야 합니다. “OAuth/OIDC enterprise authorization alignment”는 너무 포괄적입니다.

### 4) 확인이 필요한 구체 기술 주장
다음은 반드시 사양의 규범 문구와 대조해야 합니다.

- `Mcp-Method` 헤더
- `ttlMs`를 이용한 tool-list 캐싱
- 모든 세션 handshake 제거
- round-robin 로드밸런싱의 공식 보장
- JSON Schema 2020-12 “full support”
- Tasks의 experimental 졸업
- Python·TypeScript·Kotlin SDK 동시 업데이트
- Microsoft Foundry와 Google Cloud의 “즉시 통합”
- Tina Schuchman 및 Anna Berenberg의 직함·인용

이 중 하나라도 공식 문서에 없으면 기능 또는 인용을 만들어낸 것이 됩니다. 특히 사양 발표와 클라우드 제품의 즉시 상용 통합은 별도의 사건이므로 각각 공식 링크가 필요합니다.

### 5) 기존 MCP를 지나치게 왜곡
비교표의 다음 설명은 과도합니다.

> “Legacy MCP required deep packet inspection and sticky gateway routing.”

상태 유지가 필요한 배포였다고 해서 프로토콜이 반드시 **deep packet inspection**을 요구한 것은 아닙니다. DPI는 보안·네트워크 장비의 구현 선택이지, 일반적인 세션 라우팅과 동의어가 아닙니다.

### 6) 비용 효과도 근거 부족
Stateless 전송은 서버 수평 확장을 단순화할 수 있지만 다음을 자동으로 줄이지는 않습니다.

- LLM token caching 비용
- 모델 추론 비용
- 도구 호출 자체의 지연
- 인증 검증 비용
- Task 저장 비용

“token caching overhead를 낮춘다”는 주장은 삭제하거나 별도 벤치마크가 필요합니다.

### 수정 권고
공식 사양의 실제 변경 목록을 다음 네 층으로 나누는 것이 좋습니다.

1. Transport 변경
2. Protocol lifecycle 변경
3. Authorization 변경
4. Optional extension 변경

그리고 “final specification”인지, release candidate인지, extension proposal인지 명시해야 합니다.

## Item 4 — Intel 18A·RAMP-C 완료

### 판정: **프로그램 완료 사실이 확인되더라도 기술·생산성 결론은 과장**

Category 6의 7일 예외는 적절히 적용되어 있습니다. 따라서 시의성 자체는 문제가 아닙니다.

### 1) 프로그램 명칭의 역사적 정확성
RAMP-C는 2021년 **미국 국방부(Department of Defense)** 체계에서 시작된 프로그램입니다. 2026년의 현행 기관 표기가 “Department of War”라고 하더라도, 역사적 설명에서는 다음과 같이 쓰는 편이 정확합니다.

> “당시 U.S. Department of Defense가 시작한 RAMP-C 프로그램”

또한 약어는 일반적으로 기관 명칭 변화와 무관하게 계약·프로그램의 공식 명칭을 따라야 합니다.

### 2) RAMP-C 완료가 Intel 18A 상업 양산 준비를 입증하지는 않음
프로그램에서 test chip, prototype 또는 tape-out을 성공했다고 해도 다음을 자동으로 입증하지 않습니다.

- 상업적 대량생산 수율
- 고객 제품의 qualification 완료
- 목표 원가 달성
- 고수율 HVM
- 방산용 인증 완료
- 장기 신뢰성 검증 완료

따라서 다음 문장은 논리적 비약입니다.

> “confirms the commercial volume readiness”

권장 표현:

> “Intel 18A 기반 고객 프로토타이핑과 설계 생태계의 주요 기술 이정표를 달성했다.”

### 3) Secure Enclave와 RAMP-C를 혼합
Intel의 Secure Enclave 관련 정부 지원·생산 체계는 RAMP-C와 연관될 수 있지만 **동일 프로그램이라고 볼 수 없습니다**. RAMP-C 완료가 곧바로 “Secure Enclave 생산시설 내에서 전체 파이프라인이 검증됐다”는 뜻인지 공식 발표를 확인해야 합니다.

### 4) PowerVia 설명의 절대 표현은 잘못됨
다음 표현은 지나치게 절대적입니다.

- “moving power rails entirely to the rear”
- “zero top-side power congestion”
- “top-side metal layers exclusively for signal routing”

Backside power delivery는 주요 글로벌 전력 분배망을 후면으로 이동시켜 전면 배선 혼잡을 줄이는 기술이지만, 셀 내부 연결과 로컬 전원 연결까지 포함해 모든 전력 관련 구조가 전면에서 사라진다고 단정할 수 없습니다.

권장 표현:

> “주요 전력 분배를 웨이퍼 후면으로 이동해 전면 BEOL의 전력·신호 배선 경쟁을 크게 완화한다.”

### 5) RibbonFET의 리본 수는 고정된 사양이 아님
비교표의 다음 표현:

> “gate fully surrounds 4 channel ribbons”

GAA라는 “네 면을 감싼다”는 개념과 “채널 리본이 4개다”라는 물리적 개수를 혼동하고 있습니다. 나노리본 적층 수는 라이브러리·설계·공정 구현에 따라 달라질 수 있습니다.

권장 표현:

> “게이트가 적층된 나노리본 채널을 둘러싸는 GAA 구조”

### 6) “sub-2nm”의 의미 보완
Intel 18A를 sub-2nm급으로 분류하는 것은 업계 마케팅 분류상 가능하지만, `18A = 실제 1.8nm 게이트 길이`를 의미하지 않습니다. 노드명은 실제 단일 물리 치수와 일치하지 않는다는 설명이 필요합니다.

### 7) “Fully domestic pipeline”도 범위 한정 필요
미국 내 전공정 제조가 가능하다는 것과 모든 요소가 미국산이라는 것은 다릅니다.

- 소재
- 제조 장비
- 마스크
- 패키징
- HBM
- 기판
- 테스트

따라서 “fully domestic U.S. production pipeline”보다는 다음이 정확합니다.

> “미국 내 첨단 로직 전공정 생산 역량과 신뢰 공급망을 강화”

# URL 및 출처 구성에 대한 공통 문제

초안은 각 항목에 여러 출처명을 나열하지만 실제 링크는 하나만 제공합니다. 이 방식으로는 기업명·수치·직함·인용을 교차 검증할 수 없습니다.

각 항목에 최소한 다음 링크를 별도로 제공해야 합니다.

1. 회사 공식 보도자료
2. 상대 회사 공식 보도자료
3. 정부 또는 표준 사양 원문
4. Reuters 등 독립 매체
5. 필요하면 SEC 공시·계약 문서
6. 게시 시각이 표시된 원문

특히 “Source: Reuters”라고 적었다면 Reuters URL과 기사 게시 시각이 반드시 있어야 합니다.
