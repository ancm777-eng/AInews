### 시간 메타데이터 문제

1. 1번과 2번의 `16:50 EDT`가 동일한 것은 실제 기사 게시 시각이 아니라 **수집 시각**일 가능성이 있습니다. 이를 `Source Date`로 쓰면 안 됩니다.

## 1. Claude Fable 5.1·Mythos 5.1

### 판정: **핵심 사실 검증 실패 — 직접 출처 확보 전 보류**

초안이 주장하는 제품명과 기능은 모두 매우 구체적이지만, 이를 입증할 수 있는 자료가 사실상 **URL 한 개와 출처명 나열**뿐입니다. 다음은 개별적으로 직접 확인되어야 합니다.

- `Claude Fable 5.1`, `Claude Mythos 5.1`
- `claude-fable-5-1`, `claude-mythos-5-1`
- Project Glasswing
- Enterprise Frontier Safeguards
- Terminal-Bench-Science 0.1의 52.6%
- Terminal-Bench 4.0 Coding의 +13.0%
- 1M 입력·128K 출력
- AWS Bedrock, Vertex AI, Microsoft Foundry 동시 GA
- Cognition의 “모든 Opus 5 트래픽” 이전

Anthropic의 기존 제품 계층인 **Opus·Sonnet·Haiku와 전혀 다른 명명 체계**를 도입한 것 자체는 불가능하지 않지만, 그만큼 공식 모델 카드·가격표·API 문서가 반드시 필요합니다. 제시된 뉴스 URL만으로는 모델 ID, 제한 접근 정책, 가격, 벤치마크를 모두 교차검증할 수 없습니다.

### 명확하거나 계산상 중요한 문제

1. **“52.6% Accuracy”라는 표기**
   - 벤치마크 공식 지표가 정확도인지, task success rate인지 확인되지 않았습니다.
   - 공식 메트릭 명칭을 그대로 써야 합니다.

2. **“+13.0% improvement”**
   - 13% 상대 개선인지, **13.0 percentage points**인지 불명확합니다.

3. **“캐시 가격 75% 인하 → 전체 비용 25~45% 절감”**
   - 캐시 적중률, 입출력 토큰 비중, 캐시 쓰기 가격이 없으므로 산출할 수 없습니다.
   - 예시 워크로드와 계산식을 제시하거나 삭제해야 합니다.

4. **“1-million-token KV-cache reuse”**
   - 1M 컨텍스트 지원이 곧 전체 1M 토큰의 KV 캐시 재사용을 보장하는 것은 아닙니다. 캐시 가능한 블록, TTL, 최소 토큰, 쓰기 비용 등을 구분해야 합니다.

5. **EFS 약어**
   - AWS 문맥에서 EFS는 이미 **Amazon Elastic File System**을 의미합니다. “Private VPC EFS”는 두 제품을 혼동하게 합니다. 실제 공식 명칭이 맞다면 처음부터 풀어 쓰고 Amazon EFS와 무관하다는 점을 명시해야 합니다.

### URL·출처 보완

다음 직접 링크가 최소한 필요합니다.

- Anthropic 공식 발표
- Anthropic 모델 카드 및 API 모델 목록
- Anthropic 공식 가격표
- AWS Bedrock 모델 지원 공지

## 2. Anthropic–Lambda 350MW·350억 달러 계약

### 판정: **핵심 거래 구조를 입증할 원문 부족 — 보류**

다음 네 층의 계약 관계가 각각 별개의 법적 사실입니다.

1. Hut 8이 시설 개발자·임대인인지
2. NVIDIA가 15년 시설 임대차의 직접 임차인인지, 보증인인지
3. Lambda가 시설 전대차 또는 운영계약의 당사자인지
4. Anthropic이 350MW 전량을 6년간 인수하는지

초안은 이를 하나의 확정된 구조로 서술하지만, **Hut 8 공시, NVIDIA 공시, Lambda 발표, Anthropic 발표 중 어느 것도 직접 연결하지 않았습니다.** WSJ·FT·Forbes 등 출처명만 나열하는 것은 엄격한 검증이 아닙니다.

### 보완 또는 수정이 필요한 사항

1. **“NVIDIA directly holds the underlying 15-year facility lease”와 “Primary Lease Guarantor”**
   - 직접 임차인과 보증인은 법적으로 다른 역할입니다.
   - 표에서는 `Primary Lease Guarantor`, 본문에서는 `head lease holder`라고 해 서로 일치하지 않습니다.
   - 원계약 표현에 따라 `lessee`, `guarantor`, `backstop provider` 중 하나로 통일해야 합니다.

2. **약 196억 달러의 15년 계약 가치**
   - 산식과 포함 범위가 없습니다.
   - 기본 임대료인지, 전력·운영비·증액 조항을 포함한 총 계약 의무인지 밝혀야 합니다.

3. **350억 달러 / 6년 / 350MW**
   - 단순 환산하면 연간 약 58.3억 달러, MW당 연간 약 1,667만 달러입니다.
   - GPU·네트워크·운영비까지 포함한 완성형 컴퓨트 서비스라면 가능하지만, 시설 임대료와 혼동해서는 안 됩니다.

4. **“350MW 전체의 anchor off-taker”**
   - 예약 전력, IT load, utility capacity, campus gross power가 구분되지 않았습니다. 데이터센터 보도에서 MW는 같은 의미가 아닙니다.

5. **누적 1,800억 달러 예약**
   - 구성 계약 목록과 중복 제거 방법이 없습니다.
   - 450억 달러 Nscale 계약도 직접 출처가 필요합니다.

6. **“site engineering and substation bring-up underway”**
   - 상업 계약 체결만으로 공사·변전소 상태를 추론할 수 없습니다. ERCOT interconnection 문서 또는 Hut 8의 공사 현황이 필요합니다.

### URL 문제

Forbes의 단일 URL만으로는 복잡한 임대·보증 구조를 확인하기 어렵습니다. 적어도 다음 자료를 제시해야 합니다.

- Hut 8의 SEC/SEDAR+ 공시 또는 투자자 발표
- Lambda의 공식 보도자료
- NVIDIA의 계약 의무 공시
- Anthropic의 계약 확인

**결론:** 거래가 실제 보도됐더라도, 현재 초안은 **임차인·보증인·운영자·최종 수요자의 법적 역할을 단정적으로 합성**했습니다.

## 4. Arm 136코어 AGI 서버 CPU

### 판정: **시간 검증 불완전 + 기술적 모순 다수 — 대폭 수정 필요**

### 명확한 산술 모순

초안은 다음을 동시에 주장합니다.

- 칩렛당 70코어
- 칩렛 2개, 총 140코어
- “four reserved for yield recovery”
- 활성 코어 136개
- 다른 부분에서는 “70 cores per chiplet with 4 redundant cores”

가능한 경우는 다음 둘뿐입니다.

- **패키지 전체에서 4코어 비활성:** 140−4=136
- **칩렛마다 4코어 비활성:** 140−8=132

따라서 “칩렛마다 4개”라는 의미라면 136코어와 모순입니다. 정확히 **칩렛당 68 활성 + 2 예비**인지, 패키지 전체 4개 예비인지 명시해야 합니다.

### 기타 기술적 문제

1. **캐시 수치**
   - 코어당 2MB L2 × 136코어 = 272MB입니다.
   - 그런데 초안은 이를 별도의 `System-Level Cache (SLC)` 272MB처럼 표기합니다.
   - 272MB가 사설 L2 총합인지 실제 공유 SLC인지 구분해야 합니다.

2. **2TB/s UCIe**
   - 256 lane × 32GT/s를 가정하면 약 1.024TB/s/방향이고, 약 2.048TB/s는 양방향을 합한 수치입니다.
   - 따라서 반드시 **“약 2TB/s aggregate bidirectional, 약 1TB/s per direction”**이라고 써야 합니다.
   - `16x16 array`가 256개 lane인지, 16개의 16-lane 모듈인지도 정의가 필요합니다.

3. **DDR5-8800 대역폭**
   - 12 × 8바이트 × 8.8GT/s = **844.8GB/s**로 이론상 계산은 맞습니다.
   - 다만 이는 peak bandwidth이며 실제 지속 대역폭이나 sub-100ns 지연을 보장하지 않습니다.

4. **6TB 지원**
   - 6TB는 채널 수만으로 산출되지 않습니다. 채널당 DIMM 수, DIMM 용량, RDIMM/MRDIMM 지원이 필요합니다.

5. **“300W이므로 air-cooled”**
   - TDP만으로 공랭 여부를 확정할 수 없습니다. 섀시, 소켓 밀도, 허용 흡기 온도에 따라 달라집니다.

6. **“sub-micron bump pitch alignment”**
   - 서브마이크론은 정렬 오차 정밀도일 수는 있어도 일반적인 **bump pitch** 자체를 의미하기 어렵습니다.
   - `sub-micron placement/alignment accuracy`와 `tens-of-microns bump pitch`를 구분해야 합니다.

7. **AMD EPYC Turin 패키징**
   - Turin을 일괄적으로 `2.5D Multi-Chiplet`으로 분류하는 것은 부정확합니다. 일반적인 CCD+IOD 유기 기판 MCM 구조와 2.5D 인터포저 패키징은 구별해야 합니다.

8. **“I/O die로 인해 single-thread agent latency가 악화”**
   - NUMA 위치, 캐시 적중률, 메모리 배치에 따라 달라집니다. 에이전트 오케스트레이션에 특화된 효과로 단정할 근거가 없습니다.

9. **Meta·OpenAI·Cloudflare 샘플링 및 OEM**
   - 고객 샘플링과 Supermicro·Lenovo·ASRock Rack 출하 일정은 별도 공식 발표가 필요합니다. 기술 세션만으로 고객 관계를 추정해서는 안 됩니다.

10. **Tom’s Hardware URL만으로 부족**
   - Hot Chips 프로그램, 발표 슬라이드, 논문 또는 Arm 공식 기술 문서를 직접 링크해야 합니다.

### 시간 판정
