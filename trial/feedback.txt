## 1. KST 시간 윈도우

검증 기준 시각은 **2026년 11월 12일 11:31 KST**입니다.

| 적용 기준 | 허용 구간 |
|---|---|
| 일반 기사: 최근 24시간 | **11월 11일 11:31~11월 12일 11:31 KST** |
| `slot_category: 6`: 최근 7일 | **11월 5일 11:31~11월 12일 11:31 KST** |

- **1~3번:** `2026-11-11`이라는 날짜만으로는 24시간 이내인지 확정할 수 없습니다. 발표 시각과 시간대가 필요합니다. 따라서 `event_within_24h_window: true`는 아직 입증되지 않았습니다. **그렇다고 윈도우 위반이 확인된 것도 아닙니다.**
- **4번:** 슬롯 6이므로 7일 예외가 적용됩니다. **11월 12일의 신규 실리콘 검증 발표가 실제로 기준 시각 이전에 공개됐다면 적격**입니다. 기존 발표가 11월 2일이었다는 이유만으로 탈락시키면 안 됩니다. 다만 11월 12일 자료가 새로운 측정 결과인지, 이전 발표의 재소개인지는 확인해야 합니다.
- 게시일이 미국 현지 **11월 12일**이라면 KST 기준 시각 이후일 가능성도 있으므로, 날짜 표기만으로 포함해서는 안 됩니다.

## 2. 기사별 검토

### ① Recraft Vectorizer Pro — 비교표의 기존 도구 설명은 수정 필요

**명확하게 수정할 부분**

비교표는 기존 트레이싱 도구의 예로 Adobe Illustrator의 **Image Trace**를 들면서, 생성 결과의 후편집에는 외부 소프트웨어가 필요하다고 설명합니다.

하지만 Illustrator의 Image Trace 결과는 **Expand 후 같은 Illustrator 안에서 앵커와 패스를 편집할 수 있습니다.** 따라서 이를 일반적인 기존 트레이싱 도구의 한계처럼 표현하는 것은 부정확합니다.

다음처럼 비교 대상을 좁히십시오.

> “벡터 편집 기능이 없는 생성 플랫폼에서 Illustrator 등으로 파일을 옮기는 작업을 줄일 수 있다.”

이는 “기존 트레이싱 도구에는 내부 편집 기능이 없다”는 주장과 다릅니다.

**원문 확인이 필요한 핵심 사실**

- `Vectorizer Pro`라는 정확한 제품명과 출시일
- 제시된 Recraft 블로그 URL의 실제 본문
- “dual-stage” 토폴로지 모델과 공선 제약 솔버라는 구현 설명
- **노드 수 최대 65% 감소**의 비교 대상·데이터셋·측정 방식
- SVG·EPS·PDF 지원 및 **모든 요금제 제공**
- 해당 발표에서 Anna Veronika Dorogush가 직접 발표 주체였는지

이들 주장을 확인하지 못했다고 해서 제품 출시 자체를 허위로 판정할 수는 없습니다.

**분석 보완**

- 래스터 벡터화와 **네이티브 CAD 생성**은 동일하지 않습니다. 치수·구속조건·제조 적합성을 확인하지 않았다면 CAD·CNC 연결은 활용 가능성으로 낮춰야 합니다.
- 벡터 출력이라고 해서 서버 VRAM 소비가 자동으로 감소하지는 않습니다. 앞단 이미지 생성과 벡터화 모델의 메모리 사용량을 포함한 측정이 필요합니다.
- “Adobe의 독점 해소”, “Illustrator가 불필요해진다”는 출시 사실이 아니라 시장 전망으로 구분하십시오.

### ② Hugging Face Decision Models — 공식 통합 범위와 성능 근거 확인이 최우선

**핵심 확인 대상**

다음은 기사 성립을 좌우하는 구체적 주장입니다.

- Transformers 본류에 `DecisionPipeline`, `AutoModelForDecision`, `DecisionConfig`가 실제 병합됐는지
- `Choice`, `Score`, `Noul`이 공식 명칭인지
- `/v1/systemone`이 어느 프로젝트·서비스의 엔드포인트인지
- llama.cpp·GGUF 지원이 같은 구현에 포함되는지
- MMDM의 발표일, **76.0%·37% 미만** 수치와 평가 조건

블로그 설명, 별도 라이브러리 공개, Transformers 본류 병합, 호스팅 서비스 출시는 서로 다른 사건입니다. **공식 PR·커밋·릴리스 노트·API 문서로 각각 확인해야 합니다.**

**기술적으로 단정할 수 없는 부분**

- **단일 forward pass → 확률 보정 보장:** 성립하지 않습니다. 정규화된 클래스 확률을 출력하는 것과 실제 정확도에 맞게 확률이 보정되는 것은 별개입니다.
- **구조적 출력 보장 → 결정의 정확성·결정성 보장:** 역시 별개입니다. 정해진 선택지 중 하나를 반환하더라도 의미적으로 틀릴 수 있습니다.
- **생성 루프 제거 → 항상 compute-bound:** 입력 길이, 모델 크기, 배치, 커널과 하드웨어에 따라 달라집니다.
- **KV-cache 누적 없음 → 메모리 부담 거의 없음:** 디코딩 캐시를 줄일 수는 있어도, 입력 처리와 모델 가중치·활성값 메모리는 남습니다.

**수치 보완**

`<15ms`, CPU `<50ms`, “백만 쿼리당 수 센트”는 모델·입력 길이·하드웨어·배치·동시성·과금 조건 없이는 일반화할 수 없습니다.

또한 constrained decoding은 **지원하는 문법 범위 안에서 구문적 유효성을 보장하도록 설계될 수 있습니다.** 이를 일괄적으로 “스키마 준수율 95~99%”로 묶으려면 해당 구현과 시험 조건이 필요합니다. 구문 유효성, 도구 인자 유효성, 업무 판단 정확도를 분리하십시오.

### ③ WikiTrace — 연구 결과의 범위를 넘는 결론을 완화해야 함

**저자·소속 확인**

Hugging Face Papers에 논문이 등재되거나 소개됐다는 사실만으로 **Hugging Face가 공동 연구기관 또는 공동 발표자라는 결론은 나오지 않습니다.**

제목의 “KAIST and Hugging Face Release”는 논문 저자 소속이나 공식 공동 발표가 확인될 때만 유지할 수 있습니다.

**수치 자체에서 확인되는 점**

초안의 수치를 그대로 전제하면:

- 회귀 실패율 **6.5% → 4.5%**
- 절대 감소: **2.0%포인트**
- 상대 감소: 약 **30.8%**

이는 개선을 뜻하지만 **실패 제거 또는 완전한 해결을 뜻하지 않습니다.** 본문의 “eliminate”, 요약의 “solving”, “deterministic safety rails”는 결과보다 강한 표현입니다.

권장 표현:

> “평가한 환경에서 기억으로 인한 성능 퇴행을 줄였다.”

**원문에서 확인할 사항**

- WikiTrace 명칭, 코드 저장소, 실제 공개 여부

- 8개 환경 평균이 단순 평균인지 가중 평균인지

- `tau3-bench retail`의 정확한 벤치마크 명칭

“벡터·그래프 저장소”, “NVMe/S3 중심 비용 구조”도 논문 구현인지 작성자의 제안인지 구분해야 합니다.

### ④ Qualcomm AI250/HBC — 카드·랙 수치의 기준을 맞춰야 함

**내부 정합성 점검**

동일한 카드 구성과 십진 단위라고 가정하면:

| 계산 | 결과 |
|---|---:|
| 랙 대역폭 7.4 PB/s ÷ 카드당 133 TB/s | 약 **55.6개 카드** |
| 랙 메모리 38.6 TB ÷ 카드당 0.768 TB | 약 **50.3개 카드** |
| 랙 대역폭 7,400 TB/s ÷ AI200의 414 TB/s | 약 **17.9배** |

따라서 **대역폭 18배라는 설명은 랙 수치끼리 대체로 부합**합니다. 반면 카드당 용량과 랙 용량은 같은 카드 수로 바로 연결되지 않습니다.

이는 곧바로 허위라는 뜻은 아닙니다. 물리 용량과 사용 가능 용량, 서로 다른 랙 구성, 유효 대역폭 산정 방식이 섞였을 수 있습니다. 다만 현재처럼 하나의 일관된 사양표로 제시하려면 다음을 밝혀야 합니다.

- 랙당 카드 수
- GB/TB와 GiB/TiB 구분
- 물리 용량과 사용자 가용 용량
- 물리 대역폭과 압축·재사용 등을 반영한 유효 대역폭
- AI200과 AI250의 비교 구성

**반드시 원문 확인이 필요한 주장**

- 11월 12일 실리콘 검증 발표와 해당 Qualcomm URL
- HBC가 정확히 어떤 메모리·본딩 구조를 쓰는지
- **133 TB/s**, **HBM4 대비 5배 bandwidth/W**의 측정 범위
- **4~8배 tokens/W**의 모델·정밀도·배치·지연 조건
- AI250 샘플링 일정과 AI300·54배 로드맵
- ORv3, 공랭·수랭 지원의 정확한 적용 시스템

특히 **메모리 인터페이스의 에너지 효율**과 **전체 시스템의 tokens/W**는 서로 다른 지표입니다. 실측치와 전망치도 분리해야 합니다.

**분석 보완**

- 수직 적층은 데이터 이동 에너지를 줄일 수 있지만, **전체 열밀도가 낮아진다고 자동으로 결론 내릴 수는 없습니다.** 초안의 열밀도 감소 주장과 뒤의 열 결합 위험 설명 사이에 조건을 명시하십시오.
- LPDDR 계열 기술을 활용한다는 사실이 기존 모바일 DRAM 공급망을 그대로 사용할 수 있음을 보장하지는 않습니다.
- 대역폭만으로 “10조 파라미터 모델 서비스 가능”을 입증할 수 없습니다. 정밀도, 총 메모리, 분산 구성과 통신 조건이 필요합니다.

제시된 네 URL은 주소 형식만으로 진위를 판정할 수 없습니다. **응답 상태, 리디렉션, 본문 제목·날짜, 해당 주장과의 일치 여부는 미확인**입니다. 이를 확인된 공식 출처로 표시해서는 안 됩니다.
