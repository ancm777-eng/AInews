**3번 기사는 기재된 사건일을 KST 기준으로 적용하면 24시간 윈도우를 위반하므로 교체 대상입니다.** 2번에는 합계·회계 기준의 명확한 문제가 있고, 4번에는 면적 증가에 따른 생산량 감소 계산과 기술적 인과관계의 보완이 필요합니다.

## 2. 기사별 사실관계 및 수정 사항

### ① Gemini 4 Carbon — 핵심 사실의 원문 확인 필요

**명확하게 지적할 수 있는 문제**

- **지수 점수의 18% 상승을 ‘전체 능력 18% 향상’으로 해석했습니다.**  
  50→59의 점수 증가율은 18%지만, 벤치마크 지수가 실제 능력에 비례하는 척도라는 근거는 없습니다.  
  → **“지수 9점 상승”**으로 수정하십시오.

- **취약점 식별 점수를 제로데이 악용 능력으로 확대했습니다.**  
  `SEC-bench Pro 88.2%`가 취약점 식별 성적이라면, 이를 곧바로 “exploit-discovery rate”나 인터넷 규모의 제로데이 무기화 성공률로 표현할 수 없습니다.  
  → 벤치마크의 실제 과제·채점 기준을 설명하고, 악용 위험은 별도 분석으로 분리해야 합니다.

- **1위·2위 점수 차이만으로 ‘아키텍처 우위’를 확정할 수 없습니다.**  
  터미널 에이전트 성적에는 모델 외에도 실행 도구, 프롬프트, 재시도 및 계산 예산이 영향을 줍니다.

**발행 전 반드시 대조할 사항**

- Google 공식 발표의 모델명, 발표 시각, `Fairwind Program` 명칭
- Artificial Analysis의 지수 버전, 평가일, 점수 및 모델별 평가 설정
- **입력 컨텍스트 100만 토큰과 최대 출력 100만 토큰**의 구분
- 가격·할인 조건, 제한적 API 제공 범위
- TPU v7의 공식 제품명과 `Humufish` 표기의 관계

제시된 Google·Artificial Analysis URL은 **문자열만으로 유효성이나 본문 일치를 확인할 수 없습니다.** 현재로서는 핵심 발표를 ‘검증 완료’ 처리해서는 안 됩니다.

### ② Alphabet·Microsoft 실적 — 주제 유지, 수치·분류 수정

**확정 가능한 오류**

1. **합산 분기 CapEx가 본문 수치와 맞지 않습니다.**
   - Alphabet: 513.6억 달러
   - Microsoft: 약 445억 달러
   - 합계: **958.6억 달러**

   따라서 제목과 요약의 **“분기 합산 1,000억 달러 초과”**는 제시된 표로 뒷받침되지 않습니다.

2. **서로 다른 CapEx 기준을 합산했습니다.**  
   Alphabet은 현금 CapEx, Microsoft는 금융리스 포함 금액입니다. 이를 그대로 합산한 뒤 현금 유출·FCF 부담으로 해석하면 비교 기준이 어긋납니다.  
   → 양사 모두 현금 기준을 제시하고, 금융리스 포함 투자액은 별도로 표시하십시오.

3. **클라우드 전체 매출을 AI 매출로 표현했습니다.**  
   Google Cloud와 Azure 매출의 합계는 제시값 기준 **639억 달러**이지만, 전액이 AI 매출인 것은 아닙니다.  
   → “양사 클라우드 매출 합계 639억 달러”로 수정하고, AI 기여분은 별도 공시가 있을 때만 기재하십시오.

4. **연간 투자 전망이 내부적으로 충돌합니다.**  
   개요는 양사 **각각 2,000억 달러 초과**, 표는 Microsoft **1,900억 달러 초과**라고 기재했습니다. 같은 전망을 설명한다면 통일해야 합니다.

**보완 사항**

- 제목의 음의 FCF는 **Alphabet에만 해당하는지** 명시하십시오. 표상 Microsoft FCF는 양수입니다.
- `Google Cloud`, `Azure`, `Microsoft Cloud`는 범위가 다른 지표입니다. 특히 Azure의 **절대 매출액 332억 달러**가 공식 공시인지 외부 추정인지 구분해야 합니다.
- 103%, 48%, 30% 성장률에는 보고 통화·고정환율 기준을 붙이십시오.
- 실적 수치의 1차 근거로 양사 IR 자료와 현금흐름표를 직접 연결해야 합니다. 현재 Microsoft 공식 출처 URL이 빠져 있습니다.

### ③ ComfyUI v0.43.0 — 시간 윈도우상 교체 대상

**시간 문제**

기재 사건일은 **10월 27일**, 슬롯은 `1-5`, 진행 중 사건 예외는 `false`입니다. **KST 사건일이라는 전제에서는 명백히 24시간 범위 밖**입니다. GitHub의 실제 게시 시각으로 범위 내임을 입증하지 못하면 새 기사로 교체해야 합니다.

**사실관계 문제 및 확인 사항**

- **ComfyUI 라이선스를 Apache 2.0으로 표기한 부분은 수정이 필요합니다.**  
  ComfyUI 본체는 GPL-3.0으로 알려져 있습니다. 해당 릴리스 태그의 `LICENSE`를 확인하고, 본체·커스텀 노드·모델 가중치·외부 API의 라이선스를 구분하십시오.

- **FLUX 개발사와 제공 플랫폼을 구분해야 합니다.**  
  FLUX 계열의 개발 주체인 Black Forest Labs와 fal의 호스팅·API 제공 역할을 구별해야 합니다. `FLUX 3 Max`의 개발사를 “fal Research”로 기재하려면 해당 버전의 공식 발표 근거가 필요합니다.

- **공식 코어 지원과 외부 API 노드 통합은 다릅니다.**  
  노드가 추가됐다는 사실만으로 모델 가중치 공개, 로컬 실행, 상업적 사용 허용을 뜻하지 않습니다. 각 통합을 **로컬 모델 / 외부 API / 커스텀 노드**로 구분하십시오.

- 다음 수치는 해당 릴리스 노트·PR·재현 가능한 실험이 필요합니다.
  - 고정 호스트 RAM 34% 감소
  - 제작 한계비용 90% 감소
  - 16∼24GB VRAM에서 네이티브 4K 영상 생성
  - “zero-latency” 음성 합성

특히 VRAM 요구량에는 프레임 수·해상도·정밀도·오프로딩·실행 시간을 명시해야 합니다. **이미지·영상·창작 도구라는 주제 자체는 유효하며 교체 사유가 아닙니다.**

### ④ TSMC CoWoS — 시간 적합, 계산·기술 해석 보완

**확정 가능한 계산 문제**

- **3.3배→5.5배 면적 증가가 패키지 수를 ‘거의 절반’ 줄인다는 표현은 과장입니다.**  
  면적에 단순 반비례한다고 가정하면:
  \[
  3.3/5.5=0.60
  \]
  즉 생산 가능한 수량은 약 **40% 감소**합니다. 실제 수량은 웨이퍼 가장자리 손실·배치·수율에 따라 달라집니다.

**기술적 인과관계 수정**

- 패키지 휨이 커진다는 이유로 **BSPDN이 필요하다**고 연결한 부분은 부정확합니다. BSPDN은 주로 로직 다이의 전력 공급 구조이고, 패키지 휨 대응은 기판·재료·보강 구조·열기계 설계 문제입니다.
- “전체 병목이 후공정으로 완전히 이동했다”는 단정은 완화해야 합니다. 전력·HBM·기판·전공정 등의 제약이 동시에 존재할 수 있습니다.
- 테스트 시간 증가를 고온 열사이클·소켓 피로·미세균열과 바로 연결하려면 근거가 필요합니다. 생산 전기검사, 번인, 신뢰성 시험을 구분하십시오.

**원문 확인 필요**

- 가격 인상이 **검토·협상 중인지, 확정 통보됐는지**
- 13만·20만·26만 wpm의 산정 기준과 출처
- 5.5배·14배 면적 로드맵의 양산·개발 단계
- Blackwell·Rubin 테스트 시간 배수의 비교 조건
- `V100/VR200` 제품 표기
- 특정 공장의 가동률 100%

**제목의 “준비 중”과 본문의 “확인됐다”, 세부 항목의 “논의 중”은 확정 수준을 통일해야 합니다.**

## 3. 요약·일정표 공통 수정

- 요약에 반복된 **“합산 분기 CapEx 1,000억 달러 초과”**도 함께 수정해야 합니다.
- **HBM 적층 높이와 스택 개수를 구분하십시오.** `12-layer HBM stacks`와 `12 HBM stacks`는 다른 사양입니다.
- 행사 일정은 OCP·SC26·IEDM·DesignCon 공식 사이트와 대조해야 합니다. 발표·튜토리얼·전시회 기간이 다를 수 있으므로 현재 날짜를 검증 완료로 처리할 수 없습니다.
- Amazon 실적 발표일도 미국 현지 시각과 KST를 병기하십시오.
