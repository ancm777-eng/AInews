## 종합 판정

**현재 초안은 수정 없이 발행하기 어렵습니다.** 다만 이 응답 환경에서는 실시간 웹 검색이나 URL 접속을 수행할 수 없어, 제시된 공식 발표·기사·논문의 실제 내용과 게시 시각을 독립적으로 대조하지 못했습니다. 따라서 **출처 미확인을 제품의 허위 또는 시간 윈도우 위반으로 단정하지 않습니다.**

초안 자체에서 확인되는 문제는 다음과 같습니다.

- **명확한 수치 오류:** Hy4의 FP4와 FP8 메모리 용량을 동일하게 계산했습니다.
- **성립하지 않는 추론:** 지연시간 감소를 곧바로 처리량 증가·특정 최적화 기법·전력 병목 완화로 연결했습니다.
- **근거보다 강한 표현:** 메모리·대역폭당 가격 우위를 토큰당 비용·에너지 효율 우위로 확장했습니다.
- **시간 검증 미완료:** 1~3번은 날짜만으로 최근 24시간 포함 여부를 확정할 수 없습니다.

**현재 확인된 문제만으로 기사 전면 교체를 요구할 근거는 부족합니다.** 아래 수정과 원문 확인이 필요합니다.

## 1. KST 시간 윈도우

기준 시각은 **2026년 11월 5일 10:47 KST**입니다.

| 구분 | 허용 구간 |
|---|---|
| 일반 기사: 최근 24시간 | **11월 4일 10:47 ~ 11월 5일 10:47 KST** |
| `slot_category: 6`: 최근 7일 | **10월 29일 10:47 ~ 11월 5일 10:47 KST** |

| 기사 | 초안의 사건 날짜 | 판단 |
|---|---|---|
| 1. OpenAI Images 2.6 | 11월 4일 | **발표 시각·시간대 확인 필요** |
| 2. Tencent Hy4 | 11월 4일 | **발표 시각·시간대 확인 필요** |
| 3. Confluent Streamhouse | 11월 4일 | **발표 시각·시간대 확인 필요** |
| 4. Tenstorrent 논문 | 11월 2일 | **기재된 날짜가 맞다면 7일 예외 충족** |

1~3번의 `event_within_24h_window: true`는 현재 기재 정보만으로 검증되지 않습니다. 예를 들어 11월 4일 **09:00 KST** 발표라면 윈도우 밖이고, 같은 날 **09:00 미국 동부시간** 발표라면 윈도우 안입니다.

이는 **시간 위반 확인이 아니라 검증 정보 부족**입니다. 공식 발표의 타임스탬프와 시간대를 확인해 KST로 환산해야 합니다. 4번은 하드웨어·학술 연구 예외 대상이므로 24시간 초과를 문제 삼지 않습니다.

## 2. 기사별 사실관계 및 보완 사항

### [1] OpenAI Images 2.6

**핵심 발표 사실: 원문 대조 필요**

제시된 URL의 실제 응답 및 문서를 확인하지 못했으므로, 다음을 사실로 확정하거나 허위로 판정할 수 없습니다.

- Images 2.6 및 Flare·Sunburst 명칭
- 주간 40억 장, 최저 6초, 지연시간 50% 감소
- 입력·출력 토큰 가격
- GIF·SVG 지원 범위와 ChatGPT·Codex·API 배포 범위

특히 **모델이 직접 반환하는 형식**과 **제품 또는 후처리 도구가 만들어 주는 형식**을 구분해야 합니다. 스프라이트 시트를 도구로 조립한 GIF는 모델 API의 네이티브 GIF 출력과 다릅니다. SVG 코드 생성·래스터 벡터화 역시 서로 다른 기능입니다.

**수정해야 할 추론**

1. **“지연시간 50% 감소 → 처리량 2배”는 자동으로 성립하지 않습니다.**  
   동시성, 배칭, 하드웨어, 해상도, 품질 설정 등이 같고 해당 병목이 지배적이라는 조건이 필요합니다.

2. **지연시간 개선으로 step distillation·activation pruning을 특정할 수 없습니다.**  
   서빙 최적화나 하드웨어 변경 등 다른 원인도 가능합니다. 공개 근거가 없다면 해당 구현 추정은 삭제하거나 가설로 표시하십시오.

3. **서빙 용량 증가가 곧 열·전력 병목 완화를 의미하지는 않습니다.**  
   처리량을 늘리면 총전력이 증가할 수도 있습니다. 에너지/이미지 측정값이 필요합니다.

4. **비교표의 기준이 다릅니다.**  
   모델의 생성 대기시간과 사람의 전체 제작시간을 직접 비교하지 말고, 동일한 결과물·수정 횟수·품질 기준을 제시해야 합니다.

**권장 수정:** 제품 기능, API 지원, 내부 구현 추정을 분리하고, 가격표에는 정확한 모델 ID와 적용 조건을 연결하십시오.

### [2] Tencent Hy4

**명확한 수치 오류: FP4와 FP8 메모리 계산**

770B 파라미터의 **가중치만** 저장할 때 이론적 용량은 다음과 같습니다.

| 정밀도 | 계산 | 용량 |
|---|---|---:|
| FP4 | 770B × 4비트 ÷ 8 | 약 **385GB** |
| FP8 | 770B × 8비트 ÷ 8 | 약 **770GB** |
| FP16/BF16 | 770B × 16비트 ÷ 8 | 약 **1,540GB** |

따라서 **“FP4/FP8 양자화 시 약 385GB”는 틀렸습니다.** 양자화 스케일, KV 캐시, 활성값, 런타임 버퍼까지 포함하면 실제 필요 메모리는 더 커집니다.

또한:

- **8×80GB = 640GB**이므로 FP8 가중치 전체를 GPU 메모리에 상주시킬 수 없습니다.
- **“8개 GPU가 필수 최소 구성”**도 성립하지 않습니다. 정밀도, 장치별 메모리, CPU 오프로딩, 병렬화 방식에 따라 구성이 달라집니다.
- 49B 활성 파라미터는 토큰당 계산량과 관련된 수치이지, 전체 가중치 저장량이 49B로 줄어든다는 뜻이 아닙니다.

**공개 상태 표현도 정리해야 합니다.**

제목은 이미 공개된 **open-weight 모델**처럼 서술하지만, 본문은 가중치를 앞으로 단계적으로 공개한다고 설명합니다. 다음을 구분하십시오.

- API 제공
- 가중치 다운로드 제공
- 라이선스 공개
- vLLM·SGLang의 실제 지원 버전

“공개 약속”만 확인됐다면 제목은 **“가중치 공개 계획 발표”**로 낮춰야 합니다.

**추가 확인 대상**

770B/49B, 컨텍스트·출력 길이, API 가격, 환각률·추측 오류율은 공식 모델 카드나 기술 부록과 대조해야 합니다. 오류율에는 평가 데이터셋·지표 정의·비교 모델이 필요합니다. “최초의 대규모 오픈웨이트 GUI 모델”도 비교 범위를 입증하지 못하면 삭제하는 편이 안전합니다.

### [3] Confluent Streamhouse / Lightning Tables

**핵심 확인 대상**

공식 발표에서 다음을 각각 확인해야 합니다.

- Streamhouse 발표와 Lightning Tables의 **GA가 같은 사건인지**
- AWS 제공 단계가 GA인지, 프리뷰인지
- 벡터 검색, MCP, zero-copy가 실제 출시 기능인지
- IBM과 Confluent의 당시 기업 관계
- 2027년 상반기 로드맵이 회사 발표인지 작성자 전망인지

제시된 IBM 뉴스룸 URL 형식만으로 실제 게시나 내용을 확인할 수는 없습니다.

**기술적 표현 보완**

1. **“낮은 쿼리 지연시간”과 “최신 데이터 보장”은 다릅니다.**  
   서브초 응답이 가능해도 수집 지연, 늦게 도착한 이벤트, 업데이트 반영 지연이 존재할 수 있습니다.

2. **실시간 조회가 상태 불일치나 환각을 제거하지는 않습니다.**  
   여러 테이블·도구 사이의 일관성, 트랜잭션 경계, 모델의 잘못된 해석은 별도 문제입니다. “줄일 수 있다”가 적절합니다.

3. **“복제 제거·zero-copy·인메모리 로그 직접 조회”는 각각 증명이 필요합니다.**  
   쿼리용 테이블이 별도의 인덱스나 materialized state를 유지할 수 있습니다. 저장 구조를 확인하지 않고 메모리·CPU·egress 감소를 단정해서는 안 됩니다.

4. **로드맵의 사실과 전망을 분리하십시오.**  
   `Hybrid Agent Fabric / 1H 2027`이 작성자 전망이라면 회사의 확정 일정처럼 제시하지 않아야 합니다.

### [4] Tenstorrent Galaxy / arXiv:2611.02975

**시간 적합성:** 제시된 11월 2일 공개일이 맞다면 7일 예외에 들어갑니다.

**논문 식별 확인 필요**

arXiv ID의 형식만으로 제목·저자·초록·제출일을 확인할 수 없습니다. 논문이 실제로 Blackhole Galaxy를 다루는지, 기재된 사양과 비용 비교가 해당 논문에 실려 있는지 확인해야 합니다.

**수정해야 할 표현**

1. **arXiv 게재만으로 동료심사 완료를 뜻하지 않습니다.**  
   별도 학회·저널 채택 근거가 없다면 상태는 **“프리프린트 및 시스템 측정 보고”**로 쓰십시오.

2. **메모리·대역폭당 가격 2배와 토큰당 비용 2배는 다른 주장입니다.**  
   초안의 수치는 대략 다음과 같은 약 5,000달러 기준 계산과 부합합니다.
   - 32GB ÷ 5 ≈ 6.4GB/1,000달러
   - 512GB/s ÷ 5 ≈ 102GB/s/1,000달러
   - 664TFLOPS ÷ 5 ≈ 133TFLOPS/1,000달러

   그러나 이것만으로 실제 **tokens/$ 또는 tokens/joule 우위**를 입증할 수 없습니다. 서버 전체 가격, 전력, 모델, 배치, 정밀도, 출력 품질을 맞춘 측정이 필요합니다.

3. **통신과 계산의 중첩은 통신 오버헤드 제거가 아닙니다.**  
   “일부 통신 지연을 숨긴다”로 수정하십시오.

4. **GDDR6 사용 → 낮은 열유속 → VRM 전류 변동 감소 → 디커플링 커패시터 감소**라는 연결은 입증되지 않았습니다.  
   PDN 설계는 부하 전류 변화, 임피던스 목표, 패키지·보드 기생성분 등에 좌우됩니다. 설계 자료 없이 커패시터 수 감소를 주장하지 마십시오.

5. **H100과 H200의 메모리 표기를 구분해야 합니다.**  
   일반적인 H100 SXM은 HBM3, H200은 HBM3e입니다. 두 제품을 모두 HBM3e로 묶은 비교 문구는 수정해야 합니다.

## 3. 통합 요약·행사 일정

통합 요약에서도 다음 단정을 함께 낮춰야 합니다.

- “배치 레이크하우스 제거” → **일부 실시간 운영 조회의 별도 적재 필요 감소**
- “2배 추론 비용 효율 입증” → **동일 조건의 추론 측정 확인 전에는 메모리·대역폭당 가격 비교로 한정**
- “2초만 어긋나도 전체 실행 체인 붕괴” → **업무별 허용 지연시간에 따라 실패 위험 증가**
- “최초”·“입증”·“제거” → 비교 범위와 측정 근거가 있을 때만 사용

행사 캘린더는 본문 4개 기사와 별도로 검증해야 합니다. 이번 응답에서는 공식 행사 페이지와 IR 일정을 확인하지 못했으므로 기재 날짜를 승인할 수 없습니다. 특히 **행사 전체 일정과 전시 일정**, **실적 발표와 별도 투자자 설명회**, **예상 기술 주제와 확정 세션**을 구분하십시오.
