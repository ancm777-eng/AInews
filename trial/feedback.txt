## 2. NVIDIA Open Agent Safety Platform

### 판정: 검증 실패 및 기술적 과장

### 출처·명칭 문제

1. **Linux Foundation 조직명 확인 필요**
   - “Linux Foundation’s Open Secure AI Alliance”는 널리 알려진 기존 조직명과 혼동될 여지가 큽니다.
   - AI 보안 관련 기존 조직으로는 **Coalition for Secure AI(CoSAI)** 등이 있으며, Linux Foundation에는 별도의 오픈소스·에이전트 관련 프로젝트들이 존재합니다.
   - 따라서 이번 발표로 새 조직이 출범한 것인지, 기존 조직명을 잘못 옮긴 것인지 공식 Linux Foundation URL이 필요합니다.

2. **NVIDIA Sentry의 제품 지위 불명확**
   - Sentry가 실제 상용 제품인지, BlueField-4용 참조 아키텍처인지, 단순 코드명인지 구분되지 않습니다.
   - 초안 안에서도 “reference system”, “hardware watchdog”, “monitor execution directly in silicon”을 혼용하고 있습니다.

3. **100개 이상 파트너**
   - Microsoft, Anthropic, Palantir, CrowdStrike, JPMorganChase 등을 일괄 “launch partner”로 열거하려면 공식 파트너 명단이나 공동 보도자료가 필요합니다.
   - 단순 생태계 고객·호환 업체와 공동개발 파트너는 구분해야 합니다.

### 명확한 기술적 과장

- **“Resistance to Agent Bypass: Maximum”**
  - 물리적으로 분리된 DPU도 펌웨어 취약점, 정책 오류, 관리면 침해, 비네트워크 경로, 암호화 트래픽 가시성 제한을 가집니다.
  - “maximum”은 입증할 수 없는 절대 표현입니다.

- **“Near-zero overhead”**
  - 심층 패킷 검사, PCIe 텔레메트리, 정책 평가, 로그 수집에는 지연과 처리량 비용이 존재합니다.
  - 실제 벤치마크 없이 near-zero로 단정할 수 없습니다.

- **“Deep-packet inspection … directly in silicon”**
  - BlueField는 CPU 코어, 하드웨어 가속기 및 소프트웨어를 결합한 DPU입니다. 모든 보안 판단이 고정 기능 실리콘에서 수행된다는 의미로 읽히면 부정확합니다.

- **암호화 트래픽 문제**
  - DPU가 TLS 종료 지점이나 키에 접근하지 않는다면 패킷 페이로드의 에이전트 의도를 직접 판별할 수 없습니다.
  - 따라서 네트워크 격리 능력과 “에이전트 실행 의미를 감시하는 능력”을 분리해서 설명해야 합니다.

- **호스트 실행 감시 범위**
  - DPU가 네트워크·PCIe 활동을 감시한다고 해서 에이전트의 모든 시스템 호출, 파일 변경 및 내부 추론을 관찰하는 것은 아닙니다.
  - 해당 기능은 호스트 측 OpenShell에 의존합니다.

### 수정 권고

공식 NVIDIA 페이지와 Linux Foundation 발표가 실제로 확인된다면 다음처럼 낮춰 써야 합니다.

> OpenShell은 호스트 측 정책 실행 환경을 제공하고, BlueField 기반 구성은 네트워크 및 일부 I/O 경로를 호스트와 분리된 제어면에서 격리할 수 있다. 다만 암호화 트래픽 가시성, 정책 오탐, DPU 자체의 관리면 보안은 별도 검증이 필요하다.

“prompt guardrail의 우회 저항은 zero”, “DPU 기반 방식은 maximum” 같은 비교표의 절대 등급은 삭제하십시오.

## 4. Synopsys AgentEngineer / Autopilot

### 판정: 명확한 오류 포함

### 1차 URL 문제

제시 URL:

`https://www.prnewswire.com/news-releases/...-302259104.html`

PR Newswire의 `302259104` 같은 문서 번호는 2024년경 레코드 대역과 부합하며, **2026년 9월 신규 발표 URL로 보기 어렵습니다.** URL의 제목 슬러그는 바꿀 수 있어도 숫자 ID가 실제 문서를 결정합니다. 실제 페이지의 날짜와 제목을 확인해야 하며, 현재 상태로는 2026년 9월 28일 발표를 입증하지 못합니다.

공식 Synopsys 뉴스룸 URL과 게시 시각, 제품 페이지를 추가하지 못하면 이 항목은 제거해야 합니다.

### 명확한 제품 귀속 오류

레이어 표의 다음 부분은 잘못됐습니다.

> “Direct tool APIs into Fusion Compiler, PrimeTime, VCS, **Jasper**, 3DIC Compiler…”

**Jasper/JasperGold는 Cadence의 공식 검증 제품군**입니다. Synopsys의 정식 formal verification 제품으로 나열할 수 없습니다. Synopsys 제품을 뜻했다면 **VC Formal** 등으로 고쳐야 합니다.

### 인터페이스 속도 설명 오류

> “112 Gbps and 224 Gbps across UCIe and PCIe links”

이는 서로 다른 인터페이스 체계의 속도 표현을 혼합합니다.

- 112G/224G는 주로 Ethernet 계열 고속 SerDes의 레인 속도 문맥에서 사용됩니다.
- PCIe는 세대별 GT/s로 규격화됩니다.
- UCIe 역시 해당 세대의 표준 데이터레이트와 패키지 채널 정의를 따라야 합니다.

따라서 “112/224 Gbps SerDes, UCIe, PCIe”를 하나의 링크 범주처럼 쓰면 안 됩니다.

### 벤치마크 문제

다음 수치는 각각 분모와 시험 조건이 필요합니다.

- 50배 빠른 verification closure
- 20% 높은 functional coverage
- RTL 생산성 10～30%
- 토큰 효율 2배
