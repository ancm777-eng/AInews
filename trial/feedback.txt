# 항목별 검증

## 1. IBM–NASA Lunar Foundation Model

### 판정: **핵심 발표는 개연성이 높지만 성능·응용 범위가 과장됨**

### 수정이 필요한 부분

1. **23% 수치의 의미가 일관되지 않습니다.**
   - 본문은 “23% accuracy improvement”라고 하고, 비교 부분에서는 “+23% relative detection accuracy”라고 규정합니다.
   - 상대 개선율인지, 절대 정확도 차이인 **23%포인트**인지, 특정 벤치마크 점수의 최대 개선인지 구분되지 않았습니다.
   - 또한 이 수치를 얼음·분화 지형·크레이터 전체에 일괄 적용하고 있습니다. 공식 결과가 특정 다운스트림 태스크 하나의 최고값이라면 현재 표현은 과장입니다.

   **권장 표현:**  
   > “공개된 벤치마크의 일부 다운스트림 태스크에서 기존 기준 모델 대비 최대 23%의 성능 향상을 보고했다. 지표와 태스크별 절대 점수는 원 논문·모델 카드 확인이 필요하다.”

2. **‘subsurface ice detection’은 지나치게 강한 표현입니다.**
   - 궤도 원격탐사 모델은 일반적으로 수소·반사율·온도·지형 자료로 **물 얼음 존재 가능성이나 후보 지역을 추정**합니다.
   - 현장 시추나 레이더 역산 근거 없이 “subsurface ice deposits를 직접 식별한다”고 쓰면 관측 능력을 과장합니다.

3. **“Artemis landing site assessment에 배치됐다”는 단정은 별도 근거가 필요합니다.**
   - 공개 연구 모델과 NASA의 공식 비행·착륙지 선정 운영체계에 실제 배치된 모델은 다릅니다.
   - “Artemis 관련 연구를 지원할 수 있다”와 “Artemis 착륙지 평가에 배치됐다”를 구분해야 합니다.

4. **라이선스 범위를 분리해야 합니다.**
   - 모델 가중치·코드가 Apache-2.0이어도 NASA 관측 데이터 전체가 같은 라이선스라는 뜻은 아닙니다.
   - Executive Summary의 “model alongside SomBench dataset under an Apache-2.0 license”는 모델, 코드, 데이터셋의 라이선스를 각각 확인해 표기해야 합니다.

5. **비교표의 일부 표현은 근거 없는 정성 평가입니다.**
   - “Traditional ML은 full retraining required”
   - “low resolution; false-positive boulder alerts”
   - Lunar model의 “high-resolution micro-crater & obstacle segmentation”
   
   전통적 모델도 전이학습이나 PEFT를 사용할 수 있고, 공개 벤치마크 없이 정밀도 우열을 이렇게 확정할 수 없습니다.

6. **아키텍처 명칭을 확인해야 합니다.**
   - “multi-modal foundation transformer backbone”, LoRA의 네이티브 지원, TerraTorch 통합이 각각 공식 모델 카드에 명시됐는지 확인해야 합니다.
   - TerraTorch가 LoRA를 사용할 수 있다는 사실과, 해당 모델 릴리스가 검증된 LoRA 구성·체크포인트를 제공한다는 것은 별개입니다.

### URL·출처 보완

IBM 발표 URL 하나만으로 다음을 모두 입증하기 어렵습니다.

- Hugging Face 모델 카드 직접 URL
- SomBench 데이터셋 직접 URL
- NASA-IMPACT GitHub 저장소
- 논문 또는 기술보고서
- 23% 수치가 나온 평가표

### 품질 개선

- “permanent lunar habitats and resource extraction”은 현재 Artemis의 공식 범위보다 강한 상업적 서술입니다. “지속적 달 탐사와 현지자원활용 연구” 정도가 안전합니다.
- 방사선 내성 온보드 추론 수요는 전략적 추론이지 발표된 직접 효과가 아닙니다. **사실과 전망을 분리**하십시오.
- HPSC에서 INT4/INT8이 실제 지원된다는 근거 없이 특정 정밀도 배치를 전제하지 마십시오.

## 2. Anthropic 연구자 사임과 상원 법안

### 판정: **중대한 혼합·과잉 단정. 사실 확인 전 발행 불가**

이 항목은 한 기사에서 확인 가능한 사임·발언과, 별개인 의회 협상·모델 평가 사건을 하나의 인과적 사건으로 합성한 정황이 강합니다.

### 명확한 문제

1. **공개 게시물을 “testimony”라고 부른 것은 잘못입니다.**
   - 본문상 Coxon은 사임 후 공개 글을 올렸을 뿐입니다.
   - 의회 청문회, 서면 증언 또는 위원회 제출 기록이 없다면 “Coxon’s testimony”가 아니라 **“public statement/post”**라고 써야 합니다.

2. **“사임이 법안 협상을 촉발했다”는 인과관계가 입증되지 않았습니다.**
   - 같은 날 의원들이 법안을 협상했다고 해서 사임이 직접 촉매였다고 단정할 수 없습니다.
   - 의원 또는 보좌진이 Coxon의 글을 협상 배경으로 직접 언급한 인용이 필요합니다.

3. **법안 상태가 내부적으로 모순됩니다.**
   - Overview: “actively negotiating”
   - Deep Dive: “drafting negotiated for imminent committee introduction”
   - Deployment status: “statutory text finalized in drafting; committee introduction scheduled”
   
   협상 중인 법안과 문안이 확정되고 상정 일정까지 잡힌 법안은 같은 상태가 아닙니다. 법안 번호, 공식 명칭, 담당 위원회, 원문 또는 의원실 발표가 없으므로 **“Bipartisan AI Safety Act”를 확정 명칭처럼 쓰면 안 됩니다.**

4. **법안의 구체적 의무를 공식 문안 없이 단정했습니다.**
   - 제3자 containment audit
   - frontier training run 신고
   - FTC/CISA 의무 감사
   - catastrophic-risk threshold
   - hardware-level attestation
   
   의원들이 일반적인 안전 규제를 논의했다는 기사만으로는 이런 조항을 구성할 수 없습니다. 특히 FTC/CISA 집행 체계는 공식 초안이나 의원실 자료가 필요합니다.

5. **모델의 ‘sandbox breach’를 실제 containment failure처럼 서술했습니다.**
   - 안전성 평가에서 모델이 샌드박스 이탈을 시도하거나 모의 환경에서 성공한 것과, 외부 시스템을 실제 침해한 사건은 전혀 다릅니다.
   - “documented cyber breakout incidents”, “models escaping containment”는 실세계 보안 사고로 오인될 수 있습니다.
   - `Claude Mythos 5`, `Opus 4.6`이라는 정확한 명칭과 해당 사건은 Anthropic 공식 시스템 카드·사고 보고서 링크가 반드시 필요합니다.

6. **Evan Hubinger의 직책과 확률 귀속을 정밀하게 확인해야 합니다.**
   - “Anthropic Alignment Lead”가 공식 직책인지 불명확합니다. 일반적으로 연구원·연구과학자 직함과 조직 전체의 alignment lead는 다릅니다.
   - “greater than 10%”가 Hubinger 자신의 무조건부 전체 실존위험 확률인지, 특정 조건부 시나리오인지 원문 문맥이 필요합니다.
   - X 게시물은 “telemetry”가 아닙니다. Background Stats의 “TechCrunch Telemetry”도 부적절한 표현입니다.

7. **“resigning two months before his equity vested”도 정밀화가 필요합니다.**
   - 일부 주식이 처음으로 베스팅되기 두 달 전인지, 다음 tranche인지, 전체 미베스팅 지분을 포기했는지 구분해야 합니다.
   - “forfeited unvested equity”는 회사 또는 본인 확인 없이 추정하면 안 됩니다.

8. **Hawley–Blumenthal 서한 역시 직접 링크가 필요합니다.**
   - 의원 공식 사이트, 상원 위원회 또는 공개 서한 PDF가 없다면 “formal letters”와 요구 내용은 검증된 사실로 간주할 수 없습니다.

Primary URL이 Daily Sabah의 2차 보도입니다. 다음 핵심 주장에는 직접 출처가 없습니다.

## 3. California SB 1119, “Adam’s Law”

### 판정: **역사적 선례와 법안 번호·의무 내용이 혼재. 대폭 재검증 필요**

### 명확한 오류 또는 모순

1. **“nation’s first companion chatbot statute”는 성립하기 어렵습니다.**
   - 캘리포니아는 이미 2025년에 companion chatbot 관련 안전의무를 규정한 **SB 243**을 제정한 선례가 있습니다.
   - 따라서 2026년 SB 1119가 추가 규제를 도입했더라도 “캘리포니아 최초” 또는 “미국 최초 companion chatbot statute”라고 할 수 없습니다.
   - 다른 주의 선행 법률 여부까지 확인하지 않더라도, 캘리포니아 자체 선례 때문에 현 문구는 수정해야 합니다.

2. **기존 법률과 새 법안의 의무를 구분하지 않았습니다.**
   - 자살·자해 관련 프로토콜, 이용자 알림, 미성년자 보호 의무 중 어떤 것이 기존 SB 243에 이미 포함됐고 무엇이 SB 1119에서 새로 도입됐는지 분리해야 합니다.
   - 현재 초안은 2025년 법률의 요소와 2026년 법안의 주장들을 하나의 신설 법체계처럼 합쳐 놓았습니다.

3. **“13 bills”와 개별 법안 목록의 직접 근거가 필요합니다.**
   - 주지사 발표 페이지에 서명한 13개 법안 전체 번호가 나와야 합니다.
   - SB 1119, AB 1709, AB 2246, AB 2가 실제 같은 서명 패키지인지 enrolled bill 목록으로 확인해야 합니다.

4. **AB 1709의 설명은 기존 캘리포니아 법제와 충돌 가능성이 큽니다.**
   - 미성년자 addictive feed와 알림·자동재생 제한은 기존 **SB 976**과 연결되는 영역입니다.
   - AB 1709가 정확히 동일 분야를 다루는지, `$50,000 per violation`이 어떤 행위와 어떤 단위에 적용되는지 enrolled text의 벌칙 조항을 인용해야 합니다.
   - 현재 문구처럼 “affected minor당 최대 5만 달러”로 해석할 근거는 제시되지 않았습니다.

5. **“Kids Code 2.0”은 공식 법률명인지 확인해야 합니다.**
   - 캘리포니아 Age-Appropriate Design Code는 기존 AB 2273과 관련됩니다.
   - AB 2246을 “California Kids Code 2.0”이라고 부르려면 법안 제목 또는 공식 발표의 명칭을 인용해야 합니다.

6. **정확한 기술 의무가 과도하게 구체적입니다.**
   다음 조항들은 법안 원문 인용이 필요합니다.

   - 모델 가중치 공개 전 독립 감사
   - 모든 미성년자 계정의 persistent memory 기본 비활성화
   - 12시간 내 부모 통지
   - 부모 인증 없이는 시간 제한 변경 금지
   - 연례 독립 child-safety assessment
   - private right of action
   - 단계별 2027 시행 일정

   특히 “새 모델 가중치 공개 전 감사”는 companion chatbot 서비스 규제와 foundation-model weight release 규제를 혼동했을 가능성이 있습니다.

7. **로드맵은 법률상 시행 일정이 아니라 초안 작성자의 추정처럼 보입니다.**
   - “Early/Mid/Late 2027”
   - “$25K–$50K liability active”
   - “California Superior Courts & Private Right”
   
   시행일·규칙제정 기한·집행기관·사적 소권은 법문 그대로 제시해야 합니다. 추정 일정이라면 `Analyst estimate`라고 표시해야 합니다.

8. **KV-cache 설명은 기술적으로 부정확합니다.**
   - 장기 대화 기억은 일반적으로 데이터베이스, 프로필 스토어, 검색 인덱스 또는 벡터 메모리에 저장됩니다.
   - KV cache는 주로 현재 추론 세션의 토큰 상태를 보존하는 단기 메모리입니다.
   - 법적 장기기억 제한을 “KV-cache deactivation”으로 설명하면 아키텍처를 혼동합니다.

주지사가 서명했다면 상태는 단순히 “signed”보다 **chaptered 여부와 chapter number**까지 확인하는 편이 정확합니다.

“최초”를 제거하고 다음처럼 수정하는 것이 안전합니다.

## 4. Ayar Labs–Wiwynn 투자 및 광 I/O

### 판정: **기업·제품 축은 개연성이 있으나 자금 수치, 양산 상태, 공학 수치가 과도하게 확정적**

### 검증 또는 수정이 필요한 부분

1. **투자 금액의 정의가 불명확합니다.**
   - “추가 1억5천만 달러”
   - “2026년 총 6억5천만 달러”
   - “total primary capital”
   
   이전 5억 달러가 실제 2026년 신규 주식성 자금인지, 누적 조달액인지, 전략적 약정·대출·기존 라운드가 포함됐는지 분리해야 합니다. 회사 발표가 “funding secured”라고만 했다면 이를 “primary capital raised”로 바꾸면 안 됩니다.

2. **제휴 발표를 HVM 진입으로 단정했습니다.**
   - 자금 조달과 서버 제조사 제휴는 양산 준비에 도움이 되지만, 곧바로 HVM 달성을 의미하지 않습니다.
   - 웨이퍼 공급, OSAT, 광 결합 수율, 고객 qualification, 생산량 또는 shipment가 제시되지 않았다면 “transition into HVM”보다 **“HVM 준비 및 시스템 통합을 가속”**이 정확합니다.

3. **Wiwynn을 제조 파트너로 규정할 근거가 필요합니다.**
   - strategic investor, system integration partner, co-development partner, contract manufacturer는 서로 다릅니다.
   - “rack-scale manufacturing partnership”와 “standardized CPO server trays를 공동 개발한다”는 문구는 공식 발표문에 명시돼야 합니다.

4. **TeraPHY 사양 범위를 단일 제품 사양처럼 합쳤습니다.**
   - `1.6–4.0 Tbps bidirectional`
   - `sub-3 pJ/bit`
   - `up to 16 wavelengths per fiber`
   
   TeraPHY의 세대·구성별 사양일 수 있으므로 정확한 부품 버전과 측정 기준을 밝혀야 합니다. 칩렛 자체 에너지인지 레이저·드라이버·수신기까지 포함한 링크 에너지인지도 구분해야 합니다.

5. **“pluggable optics가 total server power의 25–30%”는 과도한 일반화입니다.**
   - 네트워크 구성과 서버 유형에 따라 크게 달라집니다.
   - 특정 대규모 시스템의 I/O 전력 비중을 일반 서버 전체의 보편적 수치로 확대하면 안 됩니다.

6. **“CPO가 I/O 전력을 최대 80% 절감”도 비교 기준이 필요합니다.**
   - 어느 속도, 거리, DSP 포함 범위, 레이저 포함 여부, pluggable module 세대와 비교했는지 명시해야 합니다.

7. **448G lane과 1–2m 구리 한계를 확정한 것은 시기상조일 수 있습니다.**
   - 224G와 448G는 채널 조건, 케이블 규격, FEC, 리타이머 사용 여부에 따라 도달 거리가 다릅니다.
   - “224G/448G에서 모두 1–2m”라는 하나의 물리 한계로 제시할 수 없습니다.

8. **SuperNova의 위치 설명이 지나치게 구체적입니다.**
   - 외부 광원 또는 remote laser source라는 사실과 “compute chassis 밖의 시원한 rack zone에 장착”된다는 것은 다릅니다.
   - 발표된 폼팩터가 없다면 “열원에서 분리 가능한 외부 광원” 정도가 적절합니다.

9. **삽입손실과 온도·수명 수치가 출처 없이 확정됐습니다.**
   - 15–25 dB at 56 GHz
   - under 2 dB
   - 60°C 이상에서 severe MTBF degradation
   - 95–105°C accelerator junction
   - rack당 수십 kW 절감
   
   설계·재료·채널 길이마다 달라지는 엔지니어링 수치이므로 기술 백서나 측정 자료가 필요합니다.

10. **CPO가 faceplate 문제를 자동으로 제거하는 것은 아닙니다.**
    - 광섬유 연결점, blind-mate connector 또는 외부 광원 연결은 여전히 필요합니다.
    - 시스템 토폴로지에 따라 전면이 아닌 후면·미드플레인으로 이동할 수 있을 뿐입니다.

11. **“all major accelerator vendors”는 과장입니다.**
    - NVIDIA·AMD·Intel이 투자자라는 사실이 맞더라도 “모든 주요 가속기 업체”라고 부를 수는 없습니다.
    - 투자와 상용 제품 채택 역시 구분해야 합니다.

12. **“multi-core fiber”와 “multi-fiber harness”를 혼용하지 마십시오.**
    - 멀티코어 광섬유와 여러 가닥으로 구성된 fiber array는 서로 다른 기술입니다.
    - 공식 시스템이 어느 방식을 쓰는지 확인해야 합니다.

# Executive Summary 및 결론부 검증

Executive Summary는 본문보다 더 강하게 단정하므로 본문 수정과 함께 반드시 바꿔야 합니다.

### 삭제·완화할 표현

- “spurred senators … to negotiate” → 인과관계 확인 전 삭제
- “landmark bipartisan AI safety bill” → 법안 번호·초안 확인 전 삭제
- “nation’s most stringent / nation’s first” → 비교법 검토 전 삭제
- “mandatory pre-release audits / 12-hour notice / memory restriction” → enrolled text 확인 전 삭제
- “transition CPO into HVM” → “accelerate HVM readiness”
- “overcoming copper limitations across multi-rack clusters” → 실제 배치가 아니라 목표라면 미래형으로 조정
- “deployed for Artemis landing site assessment” → 공식 운영 배치 확인 전 삭제

최종 시스템 다이어그램도 서로 직접 연결되지 않은 사건을 하나의 “system constraint loop”로 묶고 있습니다. 이는 전략적 해석으로는 가능하지만, **사실 요약과 분리된 ‘Analyst Synthesis’**로 표시해야 합니다.
