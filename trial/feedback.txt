## 2. 기사별 검증

### ① Runway App Studio — 주제 유지 가능, 제품 사양과 비교표 보완 필요

**명확한 오류·과도한 단정**

- **“Native zero-latency integration”**  
  API 호출, 모델 추론, 전송에 지연이 발생하므로 실제 처리 지연이 0이라는 기술 사양으로 제시할 수 없습니다. “네이티브 모델 연동”으로 수정하고 지연시간 주장은 삭제하십시오.
- **“ComfyUI … requires 16GB+ VRAM”**  
  ComfyUI 전체의 보편적 최소 사양이 아닙니다. 필요한 VRAM은 모델, 해상도, 양자화, 오프로딩 등에 따라 달라집니다.
- **ComfyUI를 로컬 실행으로만 구분**  
  원격 GPU·클라우드에서도 실행할 수 있습니다. 비교표는 “로컬 또는 원격 GPU, 구성에 따라 상이”로 수정해야 합니다.

**공식 원문 확인이 필요한 사항**

다음은 발표문·제품 문서에서 각각 확인해야 하며, 현재로서는 사실로 인증할 수 없습니다.

- `App Studio`라는 정확한 제품명과 제시 URL의 실제 본문
- 30초 미만 앱 생성
- Gen-4/4.5, `praxis`, 음성·스테레오 오디오 지원 목록
- KPF 및 할리우드 제작사의 실제 참여 사례
- Character Swap·AutoComp·Product Portfolio라는 출시 앱
- Brand Kits·커스텀 LoRA 지원
- 모든 유료·기업 요금제 대상 일반 제공
- 생성 코드 내보내기 및 외부 모델 연결의 불가능 여부

**보완 방향**

“Adobe 대체”와 “더 높은 매출총이익률 확보”는 발표 사실이 아니라 전망입니다. 앱 제작 지원이 곧 타임라인 편집, 합성, 색 관리의 대체를 뜻하지는 않습니다. **확인된 지원 기능과 전략적 해석을 분리**하십시오.

### ② Hi3D V1.0 — 주제 유지 가능, 제조 적합성 해석을 크게 축소해야 함

**명확한 논리적 오류**

- **슬라이싱 성공률 90% → 산업 제조용으로 검증 완료**  
  슬라이서가 모델을 처리할 수 있다는 것과 실제 출력 성공, 치수 정확도, 기계적 강도, CNC 가공 적합성은 서로 다릅니다.  
  특히 **3D 프린팅 슬라이싱 성공률을 CAM 전반의 성공률로 확장할 수 없습니다.**
- **“Watertight” → “zero interior voids”**  
  수밀한 표면이라는 속성만으로 내부 공동이 없다고 결론낼 수 없습니다. 닫힌 내부 공동을 포함하는 형상도 가능합니다.
- **NeRF·Gaussian splatting 결과가 일괄적으로 제조·게임 엔진에서 실패한다는 서술**  
  이들은 기본적으로 장면 표현·렌더링 방식이며, 메시 추출과 후처리 방식에 따라 결과가 달라집니다. 표현 방식 자체를 불량 메시와 동일시하면 안 됩니다.

**원문 확인이 필요한 핵심 사항**

- Hi3D V1.0과 Sparc3D의 정확한 관계
- 가중치·추론 코드의 공개 저장소와 라이선스
- 50만→200만 데이터 증가 및 “physically verified”의 정의
- 1536³이 출력 격자 해상도인지, 유효 해상도인지
- 90% 평가의 표본 수, 슬라이서, 설정, 성공 기준
- Progressive Octree Transformer, epipolar 제약 등 제시된 아키텍처

보도자료와 이를 재전재한 매체는 **독립된 교차 검증 자료가 아닙니다.** 모델 카드·저장소·기술 보고서가 필요합니다.

**보완 방향**

“verified 90%” 대신, 독립 평가가 없다면 **“회사 발표 기준 90%”**로 표현하십시오. “최초의 오픈소스 3D 기반모델”이라는 요약문도 비교 범위와 근거가 없으면 삭제해야 합니다. 듀얼 L40S·RTX 6000 Ada 배치 예시는 실제 메모리 측정치가 없으면 권장 구성처럼 제시하지 마십시오.

기사 날짜와 실제 최초 출시일은 다를 수 있습니다. 만약 이번 발표가 기존 회사의 신규 플랫폼 출시라면 **“회사 및 플랫폼 최초 출시”라는 상태 표기만 바로잡으면 되는지**부터 확인해야 합니다. 기존 사건을 재보도한 것이라면 그때 시간 윈도우와 예외 여부를 다시 판단해야 합니다.

**명확한 오류·비약**

  저장소 호스팅과 에이전트 세션 저장은 별개입니다. 기존 플랫폼에서도 로그·파일·아티팩트·외부 저장소 등으로 맥락을 보존할 수 있습니다.
- **“eval 임계값 충족 → 안전하게 병합”**  
  정해진 테스트 통과는 안전성을 보장하지 않습니다. “조직 정책에 따른 자동 병합 판단을 지원”하는 수준으로 한정해야 합니다.
- **“15년 된 pull request”**  
  2026년 기준 PR의 역사를 15년으로 특정하는 것은 부정확합니다. “기존 PR 중심 협업 방식”으로 바꾸는 것이 적절합니다.

**보완 방향**

89배는 워크로드·파일 수·전송량·네트워크 위치·캐시 조건 없이 일반적인 플랫폼 성능으로 해석하면 안 됩니다. 또한 Git 서버 처리와 AI 평가 추론을 구분하고, Groq·TensorRT-LLM 사용은 확인된 구축 사실이 아니라면 예시임을 명시하십시오.

### ④ UMC·AP Memory DTC — 7일 예외 충족, 전기적 수치 설명 수정 필요

**명확한 오류**

1. **면적당 용량과 체적당 용량 혼용**  
   `μF/mm²`는 면적당 정전용량입니다. 이를 근거로 MLCC 대비 “체적당 10배”라고 결론낼 수 없습니다. 두께·동작 전압 등을 포함한 동등 조건 비교가 필요합니다.

2. **전류 변화율과 인덕턴스 수치의 정합성 부족**  
   초안의 `1,000 A/ns`와 `10~25 pH`를 같은 전류 경로에 적용하면:

   \[
   V=L\frac{di}{dt}=10\text{~}25\ \mathrm{V}
   \]

   이는 0.8V 이하 전원에서 단순히 “전압 강하를 40~60% 완화한다”는 설명과 연결되지 않습니다. 실제 부하 전류와 각 PDN 분기의 전류를 구분하고, 온다이·패키지 커패시터의 주파수별 분담을 설명해야 합니다. **현 수치를 그대로 나란히 제시하면 오해를 유발합니다.**

3. **전통 PDN을 PCB의 먼 MLCC만으로 설명**  
   기존 설계도 온다이·패키지·보드의 다단 디커플링을 사용합니다. DTC는 이를 전면 대체한다기보다 특정 위치·주파수 대역의 임피던스를 개선하는 요소로 설명해야 합니다.

**원문 확인이 필요한 사항**

- 제시된 PR Newswire URL의 실제 보도자료와 발표일
- 양사의 정확한 개발·제조 역할
- 1.0~1.5 μF/mm², ESL, droop 개선율
- 세 가지 패키징 위치 모두에 대한 검증 여부
- 2026년 3분기 검증 완료 및 고객 샘플링 상태

일반적인 DTC 기술의 장점을 **이번 협력에서 검증된 제품 사양**으로 바꾸어 쓰면 안 됩니다.
