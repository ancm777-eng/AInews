### 사실·수치 문제

1. **토큰 수의 단위가 불분명합니다.**
   - 본문은 `1.1 million tokens per task`라고 표현합니다.

   - 작업당 110만 토큰이라면 “token-efficient”라는 표현은 별도 비용·성공률 정규화 없이는 설득력이 약합니다.

2. **“2.2M tokens / 66 calls peer average”의 비교 집단이 없습니다.**
   - 어느 하네스, 같은 모델, 같은 최대 토큰, 같은 retry 정책인지 제시되지 않았습니다.
   - 이를 “traditional multi-file harnesses” 전체의 평균으로 일반화할 근거가 없습니다.
   - 특히 코드 구성 방식이 토큰 절감의 직접 원인이라는 인과관계도 입증되지 않았습니다.

3. **82.2%에는 재현 정보가 필요합니다.**
   - SWE-bench Verified 버전·평가일
   - 500개 전체 실행 여부
   - 모델의 정확한 API 스냅샷
   - pass@1인지 다중 시도 후 최고값인지
   - 공개 trajectory와 제출 결과 링크  
   위 정보 없이 GitHub README 또는 보도매체 수치만 인용하면 “독립 검증된 점수”로 쓰기 어렵습니다.

4. **설치 명령이 잘못 표기됐습니다.**
   - `pip install nooa v0.0.8`은 버전 고정 명령이 아닙니다.
   - 올바른 형식은 보통 다음과 같습니다.  
     `pip install nooa==0.0.8`

5. **“runtime-enforced contracts”는 과장 가능성이 있습니다.**
   - Python type annotation은 그 자체로 런타임 강제 기능이 아닙니다.
   - NOOA가 Pydantic, `typeguard` 또는 자체 validator로 실제 검사하는 경우에만 이 표현이 정확합니다.

6. **비교 대상 설명도 지나치게 단순화됐습니다.**

   - “별도 파일을 요구한다”보다는 “프롬프트·도구·상태·그래프를 별도 추상화로 관리하는 경우가 많다”가 정확합니다.

3. **Harbor evals가 “built-in”인지 불명확합니다.**
   - Managed Deep Agents 제품 기능인지,
   - 별도 평가 저장소 또는 벤치마크인지,
   - LangSmith evaluation과 연동 가능한 것인지  
   구분해야 합니다.

## 3. Cloudflare Workers AI–AI Gateway 통합

### 시간창 및 ongoing-story 예외

항목 2와 동일하게 **ongoing-story 예외가 성립하지 않습니다.**

- 원 사건은 **2026-08-07**
- “8월 8일 상세 문서 공개”만 제시됨
- 기준 시각의 최근 24시간은 **8월 9일 07:01 KST 이후**

문서가 늦게 게시됐더라도 정확한 게시 시각이 필요하며, 문서 추가가 단순 설명 보완인지 실제 기능 출시인지도 구분해야 합니다. 현재 기사는 통합 발표 자체를 재서술하고 있으므로 예외 대상이 아닙니다.

### 기능 혼합 가능성

다음 기능이 모두 동일한 Workers AI–AI Gateway 통합 릴리스에 포함됐다고 단정하기에는 근거가 부족합니다.

- 통합 `env.AI.run()`
- 외부 14+ 공급자 호출
- 통합 선불 크레딧
- 동적 다중 공급자 라우팅
- User Insights
- identity-aware agent risk scoring
- insider-risk 탐지

Cloudflare AI Gateway의 전통적인 기능에는 로깅, 분석, 캐싱, rate limiting, retry/fallback 등이 포함될 수 있지만, **사용자·에이전트의 행동 기준선을 만들고 내부자 위험을 점수화한다는 설명은 Cloudflare One, Zero Trust 또는 별도의 AI 보안 제품군 기능과 혼합됐을 가능성**이 있습니다. 공식 릴리스에서 해당 기능이 AI Gateway에 직접 귀속됐는지 확인해야 합니다.

### API 설명의 정확성

`env.AI.run()`이 다음 두 경로를 모두 동일하게 호출하는지 명확히 입증해야 합니다.

1. Workers AI에서 호스팅되는 모델
2. OpenAI·Anthropic 등 외부 공급자 API

기존 의미의 `env.AI.run()`은 Workers AI binding 호출과 연결되는 경우가 많습니다. 외부 공급자는 AI Gateway의 provider-specific REST URL 또는 OpenAI-compatible endpoint를 사용할 수도 있으므로, “단일 binding으로 14+ 공급자를 직접 실행한다”는 문구는 공식 코드 예제가 없으면 과장입니다.

또한 `/ai/ REST endpoints`는 지나치게 모호합니다. 정확한 endpoint 형식을 적어야 합니다.

### 결제 표현

“unified prepaid credit billing across edge GPUs and third-party providers”에는 다음 구분이 필요합니다.

- Cloudflare가 외부 공급자 사용료까지 재판매·통합 청구하는지
- 사용자가 자신의 OpenAI/Anthropic 키를 연결하고 Cloudflare 사용료만 별도 부담하는지
- 일부 공급자만 unified billing 대상인지

BYOK 방식이라면 “모든 외부 API의 통합 선불 결제”라는 설명은 틀립니다.

### 분석상 과장

- “Mitigates vendor lock-in”은 부분적으로만 맞습니다. 오히려 Cloudflare 고유 binding·라우팅 규칙에 의존하면 **제어면 수준의 종속성**이 생깁니다.
- “all downstream workflows … disrupted simultaneously”도 절대적입니다. 애플리케이션이 Cloudflare를 우회하는 fallback 경로를 갖고 있다면 전부 중단되는 것은 아닙니다.

### 판정

**시간창 실패로 이번 사이클에서는 제외하는 것이 원칙입니다.**  
추후 사용하려면 기능별 공식 문서 링크를 분리하고, AI Gateway 기능과 Cloudflare 보안 제품 기능을 구분해야 합니다.

## 4. Samsung Electronics–POSTECH 3D NAND 연구

### 시간창

이 항목은 `slot_category: 6`이고 `event_within_7d_window: true`이므로 **시간창상 유효합니다.**

- 이벤트: 2026-08-07
- 7일 하한: 2026-08-03 07:01 KST

따라서 이 항목을 24시간 초과만으로 stale 처리해서는 안 됩니다.

### 연구 발표 시점 구분

IEEE VLSI Symposium은 일반적으로 8월 7일 당일 열린 행사가 아닐 수 있으므로 다음 날짜를 분리해야 합니다.

- 논문이 실제 발표된 학회 날짜
- Samsung/POSTECH 보도자료 날짜
- *Nature Electronics* Research Highlight 게시일

현재의 `event_date: 2026-08-07`은 **보도자료 또는 하이라이트 날짜**로는 가능하지만, “학회 발표일”로 읽히지 않게 해야 합니다.

### 기술적 과장

1. **“solves”와 “eliminating channel resistance”는 부정확합니다.**
   - 채널 저항은 완전히 제거되지 않습니다.
   - 결정립계 저항을 줄이거나 채널 이동도·전도성을 개선한 것으로 표현해야 합니다.

2. **155단 시험 구조에서 400+단 양산 가능성을 직접 입증한 것은 아닙니다.**
   - 155-layer test vehicle 결과를 400+단으로 확장하려면 깊은 채널의 균일성, 수율, 열 예산, nickel contamination, endurance 등이 추가 검증돼야 합니다.
   - 따라서 “enabling 400-plus layer V10 BV-NAND mass production”은 지나친 결론입니다.
   - 적절한 표현:  
     **“400단 이상 세대에서 예상되는 채널 저항 문제를 완화할 잠재력을 제시했다.”**

3. **“process integration active for commercial V10 manufacturing lines”는 별도의 공식 근거가 필요합니다.**
   - 학회 발표나 research highlight만으로 양산라인 통합이 진행 중이라고 판단할 수 없습니다.
   - 파일럿, 개발라인 검증, 양산 qualification 중 어느 단계인지 명시해야 합니다.

4. **단일 방향 결정 배향과 단결정은 구분해야 합니다.**
   - 동일한 우선 배향을 가진 poly-Si라도 결정립계가 완전히 사라지는 것은 아닙니다.
   - “uniform, single-direction silicon crystal orientation throughout”가 실제 TEM·EBSD 결과를 얼마나 정확히 반영하는지 확인해야 합니다.

### AI KV 캐시와의 연결

이 연구에서 다음 결론으로 바로 이어지는 것은 논리적 비약입니다.

- 장문맥 KV 캐시를 NAND에 직접 저장
- HBF chiplet 활용
- zNAND 활용
- 패키지 열 스로틀링 해소
- 수 GB/s 성능 보장

KV 캐시는 지연시간과 쓰기 빈도 때문에 기본적으로 HBM·DRAM이 중심이며, NAND offload는 특정 계층형 메모리 소프트웨어와 workload에서만 가능합니다. 본 연구는 **NAND 셀 채널 저항 연구**이지 KV-cache 시스템 설계 연구가 아닙니다.

권장 표현:

> “향후 고용량 SSD와 계층형 AI 메모리 시스템의 용량·전력 효율 개선에 간접적으로 기여할 가능성이 있다.”

### 레이어 도식 문제

제시된 레이어 구조는 실제 3D NAND 단면으로 보기 어렵습니다.

- nickel seed layer가 전체 wordline gate stack 아래의 독립 수평 레이어인지 불명확합니다.
- seed 위치는 공정 방식에 따라 channel plug의 특정 위치나 결정 성장 시작점일 수 있습니다.
- peripheral CMOS가 array 아래에 있으면 이를 BV-NAND/CMOS bonding 구조와 연결해 정확히 표시해야 합니다.

논문의 실제 단면도 없이 “Top to Bottom” 물리 구조로 단정하지 않는 것이 좋습니다.
