    SK hynix 256GB CMM-DDR5 and MARS: Disaggregating KV Cache Pooling via CXL 3.2

    1. Executive Summary

    Modern long-horizon AI agents expand Key-Value cache buffers linearly across extended contexts, saturating premium High Bandwidth Memory and idling GPU tensor cores during memory-bound operations. SK hynix directly resolves this capacity ceiling with its second-generation 256GB CMM-DDR5 module running over CXL 3.2 within the MARS rack architecture. By operating over PCIe Gen6 at 80 GB/s bidirectional throughput with a 30% reduction in power consumption, the system completed zero-copy memory pooling with NAVER Cloud, decoupling memory expansion from fixed GPU sockets.

    Key Architectural Concepts
    • CXL 3.2 (Compute Express Link): An open, cache-coherent interconnect protocol operating over PCIe Gen6 that enables disaggregated memory pooling, direct peer-to-peer sharing, and multi-host access.
    • KV Cache Pooling: Dynamic aggregation of transformer attention states across rack-scale memory modules rather than duplicating redundant cache copies inside isolated GPU VRAM.
    • CMM-Ax (Processing-Near-Memory): Memory module logic that offloads background cache indexing, vector embedding lookups, and memory evictions directly at the controller level.

    3. Strategic Outlook & Limitations

    Despite passing major proof-of-concept benchmarks with NAVER Cloud, pooled memory over CXL 3.2 introduces a physical latency trade-off: crossing the PCIe Gen6 switch fabric incurs an added round-trip latency of 150 to 250 nanoseconds compared to local on-package DRAM channels. If distributed inference runtimes fail to predictively stage required KV Cache blocks back into high-speed memory, execution pipelines will suffer memory stalls. Furthermore, high-frequency signaling across server backplanes enforces strict signal integrity limits, requiring advanced PCB substrate materials and dedicated retimers that increase rack manufacturing costs.
